# 日志与异常运维

在 Unity 菜单 `Tools/Arknights/Diagnostics` 打开诊断窗口。按操作、级别或关键字筛选事件，选中后查看错误码、操作编号、文档版本和调用栈。重复故障显示次数以及首次/最近时间。

## 保存位置

默认日志在当前 Unity 项目的 `Library/ArknightsMapEditor/Logs`。设置保存在项目的 `UserSettings/ArknightsMapEditor.Diagnostics.json`，不进入地图文件。可改用 D 盘绝对路径。

默认单文件 10 MiB、最多 10 个文件、保留 14 天。设置范围为单文件 1 KiB–100 MiB、2–100 个文件、1–365 天。程序只清理自身轮转日志，不删除地图和其他文件。

## 排查步骤

1. 根据错误编号找到事件，记录操作名、错误码和发生时间。
2. 输入错误直接修正对应字段；引用冲突先定位依赖项。详见[错误码](error-codes.md)。
3. 查看写入状态和队列丢弃数。日志目录不可写时修改目录或恢复磁盘权限，再重试。
4. 需要复现细节时临时开启详细日志；到期恢复普通级别。
5. 导出 JSONL，或导出包含 `manifest.json` 与 `plugin.jsonl` 的诊断 ZIP。

导出包记录 Unity/插件/资源版本、队列与存储状态，不自动包含地图正文、局部草稿、异常消息中的用户路径或资源原包。日志记录并不替代地图保存或草稿恢复。

## 生命周期

后台日志线程只写普通数据。关闭 Unity 或脚本重载时执行有时限的刷新；队列满或磁盘失败会计数，不阻止正常编辑。域重载后诊断窗口从最近日志恢复事件。来源目录、保留天数与最大容量可在设置中查看。

会话 ID 在编辑器域重载后保留。嵌套操作用 `parentOperationId` 连接父操作，编辑事件以 `previousRevision` 与 `revision` 表示版本变化。历史恢复最多读取 256 条事件，每个文件读取末尾至多 256 KiB，总读取上限 1 MiB。

聚合事件保留最近最多 64 个相关事件编号及操作编号（`relatedEventIds`、`relatedOperationIds`），可用错误提示中的最近编号找到对应聚合行。

错误消息在操作所在界面显示；日志错误不会递归生成日志。重试读取不会再次提交编辑命令；保存失败不会把文档标记为已保存。
