## 1. 用户目标与批准边界

## 3. 专业插件架构与技术选择

### 3.1 总体依赖

```text
UI Toolkit 编辑窗口 / SceneView 工具
                   ↓
Editor 会话与应用命令（一次操作、事务、撤销、保存）
                   ↓
Core 文档模型 / JSON codec / 引用校验 / 目录契约
                   ↑
资源映射、文件系统、Unity Undo 等适配器

文档变更 → 增量示意渲染（派生视图，可销毁重建）
文档导出 → 原生 LevelData JSON
编辑工程 → LevelData + 独立编辑器配置文件
```

Core 不引用 UnityEngine、UnityEditor、UI 或游戏程序集。Unity 对象引用、文件选择器、主线程调度归适配层。单个编辑会话拥有单一文档写入入口，UI 不直接修改 JSON 树。

## 4. 数据、编辑和生命周期契约

### 4.1 JSON 与编辑工程

- 原生 JSON 字段名称、数组顺序、字符串/数字枚举、缺失/null/空集合严格区分；打开文件不自动补默认值。显式“新建”和“修复”才使用默认值。
- 未识别顶层和嵌套字段原样保留；编辑局部字段只能改变对应路径。数值使用确定的解析与输出策略，覆盖大整数、小数及溢出用例；不将所有数字先转 float。
- 重复 JSON 键、超深结构、超限文件、非有限数值和无效结构返回带 JSON 路径的诊断；禁止类型名反序列化、导入执行脚本或隐式远程下载。
- 原始非法文档可只读诊断/另存原文；不能将无法完整解析的数据默认为空后覆盖。
- 自定义编辑工程建议使用 `*.arkmap`（版本化 JSON），引用相对 LevelData 路径与美术映射，绝不向 LevelData 塞入插件私有字段。直接打开单个 LevelData 不强制创建工程文件。
- 保存采用同目录临时文件、成功校验后替换；失败保留原文件。覆盖前检测外部修改摘要冲突；提供另存而非静默覆盖。恢复副本不自动替换用户源文件。

### 4.2 坐标、引用与目录

- 显式定义 row/col、底部原点和 Unity X/Z 映射；高度类型是语义，示意高度通过配置映射。非正方形地图、边界、旋转视角和导入方向用测试锁定。
- 删除/插入路线、敌人引用、Branch 等通过命令完成引用重写；无法确定关联时阻止破坏性删除并列出引用位置。
- 装置预放置、隐藏输入、卡牌、原生机制触发器分类型编辑，不把所有 ID 强制变成可摆放实体。
- 目录按数据版本记录来源与已知限制；已知模板可辅助创建，未知 ID 允许保留和显示通用标记。缺少模板不等于资源不存在。
- 地块特殊 blackboard 提供原始 JSON 编辑及已验证字段表单，不能凭中文名称猜配置或依赖。

### 4.3 Undo、窗口与清理

- 编辑命令先验证再一次提交；一次拖动画笔合并为一次 Undo。开始预览和取消操作不得修改权威文档。
- Unity Undo 记录会话序列化快照；`undoRedoPerformed` 后重新解析文档并刷新派生视图，不对每个临时网格注册重复 Undo。
- 一份文档可被多个面板查看，但只由同一会话写入；另一写入会话请求打开时提示切换现有会话。
- Domain Reload、脚本重编译、关闭窗口和进入 Play Mode 均处理订阅注销、临时对象和资源释放。编辑器不要求进入 Play Mode；不自动清空用户场景。
- 示意对象使用插件拥有的临时/预览场景，不污染用户当前 Scene。退出仅销毁本会话对象；资源采用明确所有权，禁止全局清理。
- 未保存文档关闭/切换需保存、丢弃或取消；异常保留恢复文件。恢复不承诺跨重启保留全部 Undo 历史。

| 差分 | 同输入经 Web 与 C# 操作后的 JSON 语义差异 | 分类允许变化路径；发现旧实现缺陷单独记录，不能盲目匹配错误 |
| 性能 | 网格更新、拾取、绘制连续操作、窗口和场景响应 | 同硬件、同版本、同样本记录 profiler/计时与对象数；不混用批处理与交互测量 |

性能建议预算（待 P2 同机基线校准，当前不是实测）：30×30、60×60、120×120 和非方形样本；60×60 常规编辑帧耗时 p95≤33ms、一次画笔文档与脏块更新 p95≤50ms、打开≤2s；120×120 为压力样本并记录退化边界。测量覆盖冷/热路径，重复至少5轮，记录样本内容、硬件和 Editor 开销。若不足优先定位网格重建、GC、Undo 快照和标签数量，不靠缩小支持范围隐瞒问题。

快照 Undo 在大文档可能放大内存；P1/P2 必测多步绘制和历史增长。超预算时评估文档分块快照/命令日志与 Unity Undo 的单一适配，变更需补设计记录，不保留两套独立历史。

子代理最多三个，按不重叠职责使用：文档核心与测试、场景/UI、独立审查；主代理负责接口、集成、证据和状态。所有代理避免改同一文件；只有一个代理操作同一 Unity 开发工程。编写代码后立即审查；严重/高风险问题修复后才能通过阶段。Git 使用 conventional commits，审核稿不触发自动提交。

| 风险 | 处理 | 验收 |

## 骨架渲染与仿真层分离（2026-11-03）

骨架层采用 Unity 2021 Built-in 的分块 Mesh＋共享无光照 Shader。16×16 一块，每格顶面及四侧面，实际 heightType 决定高低台，buildableType 决定基础明暗；图案由顶点 UV2 索引选择，自绘程序图案避免逐格对象、Canvas及纹理图集依赖。局部修改只重建脏块。

复用本仓 prts-map/definitions.mjs 的54项视觉定义及别名，保留来源版本；本次 Shader 和网格为独立实现，不导入网页图片或游戏美术。未知ID以粉色叉标记并完整保留数据。54项定义不等于119个游戏ID全部得到专属图案；部分定义共用图案，机关状态、文字符号细节及黑板动态效果尚不模拟。

视图提供PRTS式固定立体角度、正上方俯视和原生正交/透视切换；自由旋转、平移、滚轮缩放仍由SceneView提供。拾取包含可见顶面和侧面，格间缝隙不会误绘。路线线段和装置框是编辑标记，不是寻路或运行实例。洞口为平面图案，不切割真实孔洞。

LevelData与独立工程配置仍是权威数据。未来仿真层应有独立资源/生命周期，通过同一坐标和编辑命令读取数据；骨架材质不得写回游戏地图或成为真实美术资源。视角按钮只能作用于本窗口持有且当前激活的预览stage。
