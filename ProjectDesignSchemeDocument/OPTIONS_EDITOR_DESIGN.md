# Options 结构化编辑方案

日期：2026-11-09。状态：用户已批准，逐字段表单与配套编辑代码已实施，定向测试与原草稿保全核验已完成；测试窗口已清理，刷新后的字段表单与原地图界面已核对。原始 JSON 编辑继续保留，与表单使用同一份 options 草稿。地图尺寸已迁入独立的 [MapData 模块](MAPDATA_EDITOR_DESIGN.md) 的 map 页面，全局设置只保留 options。实现与分批通过记录见[本轮验证证据](../unity/evidence/MAPDATA_OPTIONS_EDITOR_20261109.md)，界面核对范围与剩余增强均在证据中单列。

## 范围与依据

新建 LevelData 默认包含完整15字段的 options 对象。初值采用 PC 2.7.81 `Options::.ctor @ 0x18241EA80` 的赋值及托管零初始化：99、15、3、99、1.0、0.5、true、false、false、false、false、false、-1.0、0、null（按下方声明顺序）。`configBlackBoard` 初始为 null。已有文档导入、草稿恢复保持原数据；导入缺少 options 时，仍可在全局设置中显式创建空对象。

编辑目标是当前文档的 `/options`，不是运行模式选择器。「全局设置」只是工具入口，不对应一个 LevelData 序列化对象；当前进入后直接显示 options。地图尺寸由独立 mapData 模块的 map 页面负责，不作为 options 的字段、子项或全局设置的第二页。两个模块分别有明确路径、草稿和提交操作。背景音乐 `bgmEvent` 和环境音效 `environmentSe` 继续使用音乐音效层的独立入口。

固定 dump 中 `Torappu.MapData.width/height` 是标记了 `JsonIgnore` 的只读属性；LevelData JSON 的地图尺寸由 `mapData.map` 二维数组表示。界面宽高输入用于调整网格，不导出额外的 options.width/height 或 mapData.width/height 字段。

依据：[值域研究](OPTIONS_VALUE_RESEARCH_20261106.md)、[黑板逐键约束](OPTIONS_BLACKBOARD_CONSTRAINTS_20261106.md)。固定 PC 2.7.81 原生与 3,899 份样例不能代表所有热更新。89 个观测键中，79 项只有相关消费者或部分解析规则，10 项尚仅有样例；这些数字不表示完整合法键集合或效果验收。

## 页面结构

```text
全局设置
└─ options
   ├─ 路径：LevelData.options；已应用文档状态、是否有未应用修改
   ├─ [字段表单] [原始 JSON]（同一个 options 的两种视图）
   ├─ options 对象
   │  ├─ characterLimit
   │  ├─ maxLifePoint
   │  ├─ initialCost
   │  ├─ maxCost
   │  ├─ costIncreaseTime
   │  ├─ moveMultiplier
   │  ├─ steeringEnabled
   │  ├─ reachableCheckIgnoreStartTile
   │  ├─ isTrainingLevel
   │  ├─ isHardTrainingLevel
   │  ├─ isPredefinedCardsSelectable
   │  ├─ displayRestTime
   │  ├─ maxPlayTime
   │  ├─ functionDisableMask（在此字段下展开位选项）
   │  └─ configBlackBoard（在此字段下展开有序条目）
   │     └─ [索引]
   │        ├─ key
   │        ├─ value
   │        └─ valueStr
   └─ [应用 options 修改] [放弃未应用修改] [重新读取 options]

地图数据 · mapData（独立入口）
└─ map
   └─ 地图尺寸及调整操作（不增加 width/height 序列化字段）
```

以上是界面结构；页面名称、路径和操作按钮都不写入 LevelData。表单逐项遵循固定版本 Options 的15个序列化字段声明顺序，不增加部署、费用、时间等人为分组。`configBlackBoard` 保持 options 的末尾成员，不提升为与 options 并列的模块；`functionDisableMask` 的位选项也只是该字段的编辑控件。完整原始字段树仍在工作台中央。

字段名作为每行主标识，中文解释作为辅助标注；说明、样例与诊断在该字段下展开，保持字段所属关系可见。非标或未来新增成员在同一 options 对象内显示原名和原值，不丢弃、不挪入其他 JSON 容器；表单的声明顺序不要求重排原始 JSON 成员。研究中三个 NonSerialized 成员不加入普通字段表单，导入已有同名扩展成员也不能静默删除。

## 单字段交互

### 已实施增量：有来源的候选值（2026-11-09）

15 个原生字段各有独立边框。字段内先显示本关编辑控件，再显示推荐和「全部已知值与出处」。候选列表下方显示所选值和选用按钮，之后展开所选值的出处。未提供字段的出处从列表下方单独进入，收起并重开时保留该视图。黑板的当前条目编辑排在前面，原版列表替换和按键追加放入末尾的「原版黑板参考」。

保留原15字段顺序、自定义输入及同一 options 草稿，在每个字段下增加最多三项原版高频候选、全部已知值和出处。推荐依据是固定资源快照内去重 LevelData 的使用数量，不是完整合法值表或运行效果认证。当前值始终保留；构造参考值单独注明来源，不与原版频率混算，不打开即填入。候选只有显式选用才写入草稿。

全量扫描 APW 已有 ArknightsGameData 的 levels 目录，记录提交、正文哈希、排除项、缺失/null及异常；字段值、完整黑板数组及逐键完整条目分别去重，保留全部出处。相同正文的多个文件路径不重复增加推荐权重，但出处全部保留。黑板去重包含 key/value/valueStr 和扩展成员，保留大小写、条目顺序与重复键的消费边界。未知 options 字段和非标准值纳入审计，不伪装为普通字段推荐。

同时核对 APW 的 PRTSMap 本地 levels 缓存和 ArknightsGameResource 的 gamedata/levels。补充来源按来源标识＋版本＋相对路径＋正文哈希保存，允许同路径在不同来源中保留不同值；缓存没有可证明的版本时明确标为“版本未绑定”。全部已知值与出处包含补充来源，推荐排序只使用版本明确的 ArknightsGameData 主源去重频次，不把旧缓存重复加权。主源频次、全部来源去重频次和文件出处数分别保存。ArknightsGameResource 出现的三个 NonSerialized 同名导出扩展保留在审计和原始上下文中，不升级为15字段普通表单，也不生成推荐。

全部已知值可检索。每条候选值的详情按钮打开关卡树，按关卡 ID 列出匹配该值的 LevelData。按关卡号、名称、ID 或资源路径搜索，展开关卡可查看基本正文、明确声明的替换正文及各来源版本。共用正文会出现在每个引用它的关卡下，未匹配关卡条目的正文仍可查看。出处包含路径、版本、字段位置、原始值和原文件的 options，黑板逐键出处还包含条目索引。

关卡索引使用与候选目录一致的两套固定提交。资源路径由关卡表或明确的玩法关卡记录经 `levelScenePairs` 解析。PRTSMap 缓存先按同路径同正文匹配，其余只在两套原版映射一致时按资源路径关联，并在详情标记。索引匹配 10,040 个文件，另有 978 个文件归入「未匹配关卡条目」。候选的正文数与文件出处数沿用原统计。

本轮验收包括全部源记录回读、去重/计数/推荐索引/出处一致性、当前值与未知值保留、显式选择与撤销、过期/锁定草稿、无条件整页重建防护、Unity实际刷新前后原草稿比对。数据与审计产物优先置于 D 盘；插件只携带使用所需的只读索引。

实际扫描三源11,023份JSON，其中11,018份LevelData逐份回读通过；目录含563种字段原值（含三个只审计的扩展）、89个黑板键、741种保留原JSON表示的完整条目。候选解析复用文档严格入口，保留小数精确原文；相等比较支持尾零/指数等价，仍区分整数和小数。14项Python测试与30项Unity定向测试通过，原地图恢复副本逐字节一致。完整统计、来源边界及失败修复记录见[候选值验收](../unity/evidence/OPTIONS_VALUE_CATALOG_20261109.md)。

每行显示原字段名、中文解释、控件、存在状态与必要帮助入口。示例：

```text
maxLifePoint     初始生命参数     [ 15 ]        已提供
说明：关卡初始生命参数；不是运行时生命的强制上限。
参考：构造初值15；样例范围1–300，不是允许值范围。
```

- Int32采用整数输入，Single采用数字输入（支持小数和科学计数法），Boolean采用开关。非标准类型显示原始内容及诊断，不强行转换为控件默认值。
- 缺失显示“未提供”和“添加字段”，不把构造器初值画成当前值；点击添加后才在草稿中建立字段。null显示“显式 null”，不等同false/0/缺失。提供显式移除字段；可能影响语义时说明但不自动补回。
- `/options` 本身缺失或null时先显示容器状态，用户明确创建对象后再编辑。创建从空对象开始，不批量填充构造值。单字段添加/填写按钮的提示列出将使用的参考值，点击后只修改草稿，仍需显式应用；没有已实现的“批量采用构造初值”功能。
- 时间控件标明秒；不把 `-1/0`转换为通用“无限”开关。移动倍率、整数等不使用未经证明的滑块上下限。
- 每字段候选浏览器提供完整原版值与出处，黑板逐键浏览标注原版关卡及客户端版本来源。字段用途、构造初值、读取形式和原生地址保存在研究文档中。

## 功能禁用掩码

19个已知位以可搜索复选项显示，同时展示原始值、已知位和未知位。切换一位只改变该位；“全选已知位/清除已知位”也保留未知位。缺失/null/字符串枚举/数值表示独立处理；未编辑时不改变原表示。可解析的字符串表示会明确提示使用位选项后改为数值表示，并在同一 JSON 草稿中体现；尚无单独的差异预览弹窗。无法解析的枚举字符串保留原文、停用位选项。不能用ALL覆盖原值而丢弃未来新增位。

## 黑板编辑

黑板编辑嵌入 `options.configBlackBoard` 字段的展开区域，不另立「扩展参数」页。当前采用上下布局：上部虚拟化列表显示索引和键名，下部显示选中条目的 `key/value/valueStr`、完整原文及诊断，路径标明 `options.configBlackBoard[索引]`。可新增、复制、删除、上移和下移条目；重复键和大小写冲突提示，但不自动去重。null、空列表及未提供分别显示。当前没有多列黑板列表、黑板搜索或可拖动分隔线，后续增强不能改变导出顺序。

选中条目后完整显示 `key/value/valueStr`。数值读取要求valueStr为空，字符串读取要求非空；空串仍保留为空串，不能自动转换成null。数值与字符串同时存在时解释实际读取行为。扩展成员保留；数组里的非标准记录也必须可查看并定位修正。

当前已实现的是原生三字段编辑，没有按具体黑板键自动生成枚举、布尔或资源选择器。后续可按已核实证据逐项增加下列辅助控件，仍与原生字段共用同一条记录：

| 类型 | 控件及条件 |
|---|---|
| 数值布尔 | 开关写0/1；已有非标准数值保留并显示近零判断说明 |
| 已证枚举 | 相机档位、球场类型下拉；不识别值保留显示，条件与版本有说明 |
| 坐标/矩形/四数相机参数 | 完整解析格式与异常路径核实后才开放结构化助手；此前显示原文和已有样例 |
| 时间列表 | 数值单项与字符串列表分别保留，不悄悄互转或排序原文 |
| 别名/资源/任务引用 | 仅有可靠引用源时提供选择器；未加载引用源标为“未验证”，不标不存在 |
| 未知键 | 原生字段编辑本轮已实现，观测目录不作为封闭白名单 |

模式/版本信息只用于研究说明和后续诊断适用范围，不修改关卡模式或复制配套资源。相同键名不能跨模式直接套用规则。黑板整数读取是Floor，布尔使用近零比较，重复键按类型查找首个匹配；当前界面提示重复键与数值/字符串通道，不在导出时擅自改值。

## 提交、草稿与校验

一个options草稿绑定文档身份和版本，复用原来的 `global:options` 草稿槽，兼容已有原始JSON草稿。表单和原始JSON是同一草稿的两种视图；JSON存在语法错误时保留文本，并提示暂不能转表单，不回退覆盖输入。切换页面不重建控件；黑板展开和选中索引在窗口中序列化保存。应用一次只替换或明确移除 `/options`，产生一次撤销，其他顶层字段不变。

编辑锁禁止应用和修改，与既有模块行为一致。切图、关闭和域重载接入既有草稿恢复，不因当前焦点变化写入另一地图。无局部修改时刷新到当前文档；有修改时保留草稿，文档版本变化后显示过期提示并拒绝直接覆盖。显式重新读取/放弃未应用修改沿用确认流程。专门的差异查看界面尚未实现，可通过原始JSON查看当前草稿。

存储类型校验和原生数值提示分别处理：

1. 已实施：严格JSON语法、修改字段的实际类型、Int32范围、Single可表示的有限值，以及黑板条目修改的原生类型。新增/修改错误不提交，保留待修草稿。未改变的旧异常保留，不打开即规范化。
2. 字段旁的数值提示引用 PC 2.7.81 原生消费路径。自然回费初始化按 Single 转 FP 的量化结果判断计时器是否启用，阈值为 raw 42950。初始生命非正时标出初始化值，移动倍率为负时标出固定方向位移的速度项。回费周期、移动倍率和最大游玩时间超出 FP 可转换范围时显示提示；最大游玩时间的结束语义仍由具体模式解释。
3. 提示随草稿刷新，保留原值及表示，允许应用和撤销。缺失、null 和类型不符分别沿用已有显示及类型校验。FP 后续运算边界、按键原生约束与资源引用诊断仍在后续计划。

不能让未修改的旧问题导致其他无关字段无法编辑。本轮应用失败直接显示具体校验消息；应用前差异摘要待增强。原始文档导出继续遵守现有严格JSON契约，不引入“自动修复全部”或新的运行启动行为。

## Unity 前端实现方式

沿用当前 Unity 2021.3 插件的 UI Toolkit。options 字段按声明顺序使用 IntegerField、FloatField、Toggle、TextField 等原生控件；`configBlackBoard` 展开区域使用 ListView 虚拟化，上下排列列表与详情，没有使用 TwoPaneSplitView。官方编辑器扩展示例可用于后续分隔面板与布局增强：[Unity 2021.3 — Create a custom Editor window](https://docs.unity3d.com/2021.3/Documentation/Manual/UIE-HowTo-CreateEditorWindow.html)。

UI 绑定编辑器自己的 JSON 草稿模型，不依赖游戏运行程序集或实例化游戏 Options。字段元数据保存原名、中文说明、类型、显式添加时的参考值与帮助文字；只读取值目录保存完整观测值、出处及版本身份，逐键说明保存固定版消费研究的适用边界。目录不能转换成封闭合法值表。输入更新现有控件，避免重建整页；黑板数量不变时刷新列表项，数量变化时保留已有滚动偏移和选中索引。候选与出处列表虚拟化，选用候选时同步选中高亮而不收起出处面板；缺失字段的出处单列，浏览不隐式创建字段。
