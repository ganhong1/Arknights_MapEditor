# 敌人资源库数据与联动设计

2026-11-12；已认可并进入实现。波次结构化编辑暂缓；敌人资源库和定义编辑本轮落地。版本目标 PC 2.7.81。

## 原生结构与职责

```text
固定来源 EnemyDatabase
└─ enemyId → EnemyLevel[]
   ├─ level
   └─ enemyData: EnemyDatabase.EnemyData（可继承的定义）
      ├─ name / description / prefabKey
      ├─ attributes（每项独立Undefinable）
      ├─ applyWay / motion / enemyTags
      ├─ lifePointReduce / levelType / rangeRadius
      ├─ numOfExtraDrops / viewRadius / notCountInTotal
      ├─ talentBlackboard
      ├─ skills[]
      │  ├─ prefabKey / priority / cooldown / initCooldown / spCost
      │  └─ blackboard
      └─ spData: spType / maxSp / initSp / increment

LevelData
├─ enemyDbRefs[]: EnemyDataDbReference
│  ├─ useDb: bool
│  ├─ id: string
│  ├─ level: int
│  └─ overwrittenData: EnemyDatabase.EnemyData
├─ enemies[]: LevelData.EnemyData（实际值型定义）
│  ├─ name / description / key / alias
│  ├─ attributes / applyWay / motion / enemyTags
│  ├─ notCountInTotal / lifePointReduce / rangeRadius
│  ├─ numOfExtraDrops / viewRadius / levelType
│  └─ talentBlackboard / skills / spData
├─ waves[].fragments[].actions[]
│  └─ SPAWN: key + routeIndex + count + preDelay + interval + 调度字段
└─ branches[分支key].phases[].actions[]
   └─ SPAWN: 同一动作结构，分支路线库为extraRoutes
```

两个EnemyData是不同类型。数据库的prefabKey通过EnemyDataMeta映射到实际值型的key。keyInLevel是计算属性：alias非空用alias，否则用key，不另存一份序列化字段。

数据库大部分标量和enemyTags采用Undefinable<T>{m_defined,m_value}。false代表本层未定义，true+0代表显式零。复合talentBlackboard/skills/spData不是统一Undefinable结构。

attributes的已声明数值字段：maxHp、atk、def、magicResistance、cost、blockCnt、moveSpeed、attackSpeed、baseAttackTime、respawnTime、hpRecoveryPerSec、spRecoveryPerSec、maxDeployCount、massLevel、baseForceLevel、tauntLevel、epDamageResistance、epResistance、damageHitratePhysical、damageHitrateMagical、epBreakRecoverSpeed。免疫字段：stunImmune、silenceImmune、sleepImmune、frozenImmune、levitateImmune、disarmedCombatImmune、fearedImmune、palsyImmune、attractImmune、teleportImmune、groundBoundImmune。

## 已核实合成与引用

- GetComputedEnemyData将alias设为数据库id。level<0时只应用首条定义；非负目标先检查等级存在，再按源列表顺序应用，遇到首个超过目标等级的记录停止。数据库等级不是干员练度，也不能只读取对应等级那条稀疏记录作为完整值。
- Blackboard补丁按key删除旧条目再追加新条目。技能按prefabKey匹配；补丁黑板为空时替换技能项；非空时合并旧黑板，其他技能字段来自补丁。不能用普通JSON深合并代替原生合成。
- `Scheduler.Init` 先登记成功解析的 `enemyDbRefs[]`，再按 `keyInLevel` 补充尚未占用的 `enemies[]`，随后处理 `runtimeData.extraLoadEnemies`。该优先级适用于调度器的敌人表。预加载和部分模式有自己的读取规则，见 [内联敌人的读取入口、同键优先级与版本沿革](#内联敌人的读取入口同键优先级与版本沿革)。
- SPAWN内部只查已加载敌人映射；找不到走AlertSpawnError，不自动从数据库按同名补取。
- 同一敌人变体可通过useDb=false建立：必须提供overwrittenData，从LevelData.EnemyData构造对象开始应用；id非空且不同于解析出的key时设alias=id。id等于key则直接用key。level在此路径不用于数据库查询。由此可以用不同id、相同prefabKey保存两个属性变体。不能给四字段引用对象虚构alias字段。

## 资源库单项设计（编辑器内部，非LevelData新增字段）

```text
EnemyCatalogEntry
├─ sourceIdentity
│  ├─ gameVersion / platform / resourceVersion
│  ├─ revision / fileHashes
│  └─ 版本核对状态
├─ enemyId
├─ displayMetadata：名称、图鉴、标签、头像及各自来源
├─ levels[]：原始稀疏等级定义
├─ knownReferences[]：原版四字段引用配置
│  ├─ 完整原文与内容标识
│  └─ sources：关卡 → 模式/版本 → LevelData → JSON位置
├─ inlineExamples[]：实际值型原版例子，单独展示
└─ resolvedPreview：只读合成结果、每个字段的来源
```

一张资源卡片对应一个固定来源中的enemyId，等级在卡片详情选择。不同来源版本分别标识，不按中文名合并。敌人key、prefabKey、图鉴ID分开保存，名称和图标不是主键。

原版配置去重保留useDb/id/level/overwrittenData的完整语义与未定义状态，不把spawn数量、路线、出场时间混入敌人模板。默认推荐最多三项，全部既有已知配置、当前配置出处、总出处沿用地块与装置资源库交互；推荐频次明确按固定来源去重正文计数，混合历史版本不当成当前版本频次。

## 前端与数据流

右侧“敌人”只做搜索、标签筛选、选中高亮、详情预览和选用；信息按钮复用现有图标，搜索复用项目统一算法。标签仅使用有来源的运动方式、敌人级别、标签等数据。

左侧“敌人定义”编辑当前文档。选用资源库项目时选择等级或原版引用配置，创建或复用完全一致的定义；同身份不同覆盖先提示编辑现有定义或创建独立变体，不能静默重复插入。独立变体采用useDb=false及新id；从原库派生时必须物化所需继承值到overwrittenData，不能仅复制稀疏差量，否则丢失原库继承。编辑器派生来源记录在工程元数据，不写进原生字段。

编辑页保留原四字段结构，并展示“继承值／当前覆盖／解析值”。覆盖字段提供继承和覆盖开关；取消覆盖撤去本层定义，不写零。敌人最终战斗值还受符文/模式/运行Buff影响，解析预览只展示定义合成值。

增加“引用位置”列表：waves→fragment→action、branches→phase→action。点击跳转，保留草稿、展开和滚动位置。选择敌人不自动新建wave或branch，不直接在地图格上放置敌人。后续从动作创建出怪，显式选择数量和路线。

SPAWN选择当前文档已加载的敌人身份；资源库中存在但未加入地图的条目提供“加入当前地图”操作。文档内未解析、模式运行输入、明确失配分别显示。不能以“数据库有同名”抹掉引用问题，也不自动修改导入的特殊模式正文。

更名、删除和替换先按动作类型计算引用，不能全局替换所有key字符串。敌人别名和预设alias属于不同目标域。未知动作、黑板中字符串和外部机制引用单独列待核，原文保留。

## 内联敌人的读取入口、同键优先级与版本沿革

2026-11-13 复核。原生方法以固定 PC 2.7.81 的 `GameAssembly.dll` 为准。公开 2.7.91 关卡正文用于对照版本历史。

### 两种独立定义的载入方式

| 形式 | 写入关卡的数据 | 生成本关定义 |
| --- | --- | --- |
