### 1.1 关联结构不是一套通用 ID 引用

| 关联 | 已核实内容 | 编辑器操作 |
|---|---|---|
| Legacy → Selector | enemy/char/tile/tag 等黑板字符串由转换器读取；列表按竖线拆分，保留非空片段的空格和重复 | 条件辅助表单，精确回写原行；不增加 selector 顶层字段 |
| enemy 条件 → 关内敌人 | 已有消费复核指向 keyInLevel；不是统一图鉴 ID | 提供本关敌人候选，但允许外部/动态标识；静态未匹配不能直接报不存在 |
| rune_alias → 其他 Rune | add_other_rune_blackb 通过 alias 和目标有效性筛选，可作用于多个候选 | 展示全部候选及各自路径；不要求 alias 唯一，不把关系强制改成一对一 |
| hidden group → 调度 | LHiddenGroupEnable 读取黑板 key 的字符串，加入 extraData.enabledHiddenGroups；禁用走对应集合，已有调度复核为先启用再移除禁用 | 导航到同名 waves/branches 动作 hiddenGroup；它与 selector 的 action_hidden_group 是两种关系 |
| optional 组名 → 外部选择 | 由外部 optionalRuneKeys 选择，按字典遍历筛选；组展开未做 difficulty 检查 | 组名改动列为外部契约变化，不自动改玩法或把当前页签视为启用 |
| globalBuffs.prefabKey → GlobalBuff prefab | BattleFactory.CreateGlobalBuff 加载，OnInit 后控制器持有 | 资源选择与依赖详情；不是直接选择 BuffData.buffKey |
| GlobalBuff → 下层 Buff | prefab 持有 _buffs、_deckBuffs、TargetOptions、相机和来源配置，派生组件可另加条件 | 下层数据作为资源详情；LevelData 表单只编辑六持久字段 |
| rune → 分支/预设/其他资源 | 样例有 branch_id、alias、token_key；具体含义依赖实现或被加载的 prefab | 已确认规则允许导航；样例匹配先列“原版关联”，不自动重写 |

### 1.2 同名字段的语义不能复用

TargetOptions.professionMask 的原版 Tooltip 明确 NONE 表示不使用该掩码，即等同 ALL；这是该结构的规则，不能套用到 RuneData.Selector。TargetOptions 还持有 targetSide、targetMotion、targetCategory、purposeMask、unitTypeMask、异常状态的包含/排除和高级开关。故“职业、部署、阵营”几个参数不足以决定全局效果所有命中目标。

GlobalBuff 的 prefab _key、LevelData 的 prefabKey、BuffData.buffKey、符文 key、黑板中的 key 各属自己的名称空间。界面必须显示其所处结构，后台不建立一个跨类型通用 key 字典。

### 1.3 原版配置提供的关联例子

- env_gbuff_new 的一份样例：黑板 key=cooperate_get_branch、alias=trap_097_hstone#3、branch_id=r_hstone#3。这说明一个配置可以同时携带效果资源、预设标识与分支参数；该样例本身不足以证明通用 branch_id 重命名规则。
- level_predefines_enable 的样例把 trap_124_eradio#7 等标识写在黑板 **key** 上，value=1，而不是 valueStr。只扫描 valueStr 的关联服务会漏掉这类配置。当前已证类入口，逐别名读取行为需继续看方法体后才允许自动改名。
- env_gbuff_new_with_verify 的样例可有 char=trap_020_roadblock 和 enemy=empty。char 不宜只提供普通干员；enemy 字符串不能因未匹配本关敌人就自动清除。
- level_predefine_tokens_random_spawn_on_tile 同时带 tile=tile_dygmny_3 和 token_key=trap_224_dyrbox。它是条件和资源输入，不能替换成一个固定预设坐标绑定。
- add_other_rune_blackb 的样例有数值 atk/def/max_hp、rune_alias、six_star_rune_alias。后者不能仅凭名称相似就当作 optional 组名外键并自动同步。

## 3. 前端设计

### 3.1 集合与卡片

三个页签都显示原字段名。顶部显示集合状态和数量，新增/复制/删除/重排放在列表框内。卡片显示序号、名称或原 key、目标摘要、参数数；关联问题用一个小计数入口，不堆来源说明。optional 左边选择组，右边列组内条目；窄栏上下排列，组名和当前目标始终可见。

不因切换条目折叠已展开的出处，不重置滚动，不对数组进行显示排序后自动回写。资源搜索结果可以排序，地图配置列表按保存顺序显示。

### 3.2 配置表单

严格保留原生字段顺序。每个字段或结构用独立内框；标题不加粗，绑定目标和将修改的位置重点展示。runes/optional 共用一个 Legacy 表单，globalBuff 独立表单。

黑板默认三列：参数键、数值、字符串。每行有展开、复制、移动和删除；两通道同时显示，不能只保留当前被某消费者读取的通道。已知参数可以显示专用控件，但原始行仍可展开查看。新增键从“当前实现已知键”选，也支持自定义。

selector 辅助区是 blackboard 内的一组便捷操作：列出当前筛选值和实际参数键。选择多个对象时写原版分隔字符串；若有重复键，先选择编辑哪一行，显示其他同名行，不批量替换。原文无法解析时保留原文，用户可转到原始 JSON 修改。

### 3.3 关联查看

不另建全屏节点图。配置编辑框下提供“关联”折叠区，分为：

- 本条使用：筛选条件、符文 alias、分组、资源以及已确认的分支/预设关联。
- 使用本条：被 alias 参数或已识别调用读取的位置。
- 所需上下文：可选组选择、玩法提供的目标、预制体规则。

每行显示关系名、目标、字段路径和“定位”按钮；有多个候选则展开列表。源码已确认关系与仅由原版样例匹配的关系分组显示。用户层只显示“本关已找到”“需要外部输入”“原版配置关联”等具体状态；详细依据放详情，不在主表堆技术提示。

地图高亮仅展示能够静态定位的格子/预设；筛选的是 tileKey 时可高亮本图同 key 格，显示“对应格”，不称为全部实际生效格。敌人条件定位敌人定义和相关出怪动作，不虚构出生时刻或最终效果。

### 3.4 资源详情

沿用详情 icon；默认推荐最多三项、全部既有已知配置、当前配置出处、总出处。按关卡分组，组内保留模式/版本及正文位置。配置详情展示原集合、optional 组及相关参数；复制到另一集合不会改变掩码，也不会自动附加来源关卡的分支或预设。

GlobalBuff 详情新增只读“预制体结构”：组件类型、TargetOptions、Buff/DeckBuff 列表及已定位依赖。未解析包显示实际资源定位状态，仍可查看与编辑原配置；不在六字段表单里伪造 _buffs 编辑项。

### 3.5 改名与删除

普通集合删除沿用“确定／取消”。涉及组名、别名及跨字段关系时，先显示变更清单：直接修改项、可同步关联项、外部关联项。只对已确认关系提供“同步已确认关联”；未确认字符串不批量替换。被多个候选共享的 alias 改名不自动升级为全局 alias 改名。

删除不会级联删除敌人、预设、分支或全局效果；若有待处理草稿，保留或明确确认处理。应用失败时保留输入，错误定位在相关字段。

## 4. 后端分层（Unity 包内 C#，不新增 HTTP 服务）

```text
UI Toolkit / 现有 IMGUI 表单桥
  → Application：编辑会话、局部草稿、命令预检、撤销事务
    → Core：不可变 LevelDocument 命令 + 结构校验
    → Rules：版本化参数与关联规则
    → Catalog：原版配置、推荐、出处、资源清单
    → References：本关关联索引与变更影响
  → 现有文档保存 / 恢复 / 日志服务
```

JSON/JToken 是正文权威数据；类型化投影只服务表单与校验，不能通过窄 DTO 序列化而丢掉未知字段。目录与已加载正文只读共享，选用时深复制。ResourceIdentity 至少包括基线/来源、资源种类和原 key，不把不同版本同名效果当同一实现。

### 4.1 建议接口与责任

以下是待实施接口职责，不是已存在 API：

| 服务 | 主要操作 | 输出 |
|---|---|---|
| RuneCatalog | Search / GetConfigurations / GetSources | 分页条目、完整配置指纹、来源与上下文 |
| RuneSchemaRegistry | Resolve(version, kind, key, component) | 原生字段序、参数约束、消费者关联规则 |
| RuneDocumentCommands | Add/Update/Move/Delete；组 Create/Rename/Delete | 新文档与地址变更集 |
| RuneAssociationIndex | Analyze(document, ruleRevision, resourceContext) | 带关系类型和依据的关联集合 |
| RuneChangePlanner | Preview(command, expectedRevision) | 修改路径、同步候选、问题与外部影响 |
| RuneEditSession | Apply(plan)、Undo/Redo、RestoreDraft | 单一事务结果与草稿迁移 |
| GlobalBuffResourceResolver | Resolve(prefabKey, resourceContext) | prefab/组件/依赖清单与已解析状态 |

规则应表达：资源种类、实现/组件、字段地址模式、读取通道、比较/拆分方式、目标名称空间、作用范围、是否允许重写、原生版本和证据。`branch_id` 不设为全局通配规则；黑板 key 和 valueStr 都可成为规则明确指定的读取位置。

关联记录至少包含 sourceAddress、relationKind、targetNamespace、originalValue、candidateTargets、scope、evidence、rewriteCapability。筛选条件、资源加载、组激活、参数修改和调用分别建类型。候选为空时可能是外部输入，不能一律判悬空错误。

### 4.2 数据标识与草稿

正文没有编辑器 UUID。工作区用临时 EntryId 追踪选中项和草稿，导出不写入 LevelData；命令提交维护 EntryId 与新数组地址的映射。完整相同的两条配置也有不同工作区 ID，不能仅凭配置 hash 绑定草稿。

重载恢复先核对文档 revision 与原目标快照；相同数据存在多个候选时保留为待定位草稿，不猜附着对象。组名用结构化路径或 JSON Pointer 转义。数组重排、组改名、原文应用和撤销都生成显式地址映射。

### 4.3 校验与事务

1. 结构：外层容器、字段类型、有限数值、枚举已知部分；保留历史未知数据。
2. 参数：按具体消费者证据检查键和值，不将语料范围当硬边界。
3. 关联：静态文档引用、外部资源、动态条件分别报告。
4. 提交：验证 expectedRevision；构造候选文档与草稿迁移；一次提交；成功后更新派生索引和 UI。

跨模块同步必须同一撤销事务，预检后文档变化则拒绝旧计划并重新计算。非法原始 JSON 不会被结构化表单静默覆盖。规则更新不自动修改正文；所有诊断附文档版本，旧异步结果不得覆盖新选择。

异常复用现有诊断系统：输入错误就地显示；取消不记故障；IO/目录损坏显示重试入口；内部错误附诊断编号，避免循环弹窗。日志记录操作、文档版本、路径和结果，不默认写完整黑板/正文。后台目录查询有取消与有界缓存，不调用 Unity 对象 API。

### 4.4 持久化与接口文档

LevelData 只保存原生三个字段及导入已有扩展。目录文件保存配置、出处和版本；规则文件保存消费依据；工作区保存 UI 状态、EntryId 和草稿，三者分离。依赖解析在可配置 D 盘缓存或项目既有缓存目录，禁止写回游戏原包。

内部 API 使用项目现有 XML 注释/DocFX，目录与规则文件使用 JSON Schema。现有 OpenAPI 文档只用于真实 HTTP 边界；这个模块没有新增服务，不为 Swagger 建一套多余后端。
