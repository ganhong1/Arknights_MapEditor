# 符文与增益模块：数据与编辑设计

日期：2026-11-14。状态：研究与设计完成后供评审，尚未实施专用编辑代码。原生结构基线为 PC 2.7.81；既有配置来自冻结成品地图库，保留各自模式和来源版本。

## 1. 文档与职责

- [原生结构与消费链](符文与增益原生结构研究.md)：字段、转换、筛选、调度、资源加载及未闭合问题。
- [全量语料核验](符文与增益全量样例核验.md)：8,664 份正文、完整配置去重、逐资源计数、黑板与出处。
- [现有代码与界面分析](符文与增益前后端设计.md#现有编辑组件核验2026-11-14)：可复用组件、草稿与编辑接口。
- [专项实施计划](PlanDocumentsForImplementation/UnityEditor/符文与增益实施计划.md)：后续实现和验收队列。

本模块生产 LevelData 中的三个根字段。玩法选择、玩家持有藏品、商店获得、运行时符文输入以及最终属性计算由游戏调用链承担。编辑器可以展示已确认的静态关联，不将最终战斗模拟作为编辑条件。

## 2. 数据树

```text
LevelData
├─ runes[]                                  关卡符文，有序列表
│  └─ LegacyInLevelRuneData
│     ├─ difficultyMask                     LevelData.Difficulty
│     ├─ key                                符文实现标识
│     ├─ professionMask                     ProfessionCategory
│     ├─ buildableMask                      BuildableType
│     └─ blackboard[]                       有序参数列表
│        └─ DataPair
│           ├─ key                          参数键
│           ├─ value                        数值通道
│           └─ valueStr                     字符串通道
├─ optionalRunes                            字符串键 → 符文列表
│  └─ <groupKey>[] → LegacyInLevelRuneData   与 runes 使用同一表单
└─ globalBuffs[]                            全局效果，有序列表
   └─ GlobalBuffData
      ├─ prefabKey                          效果预制体标识
      ├─ blackboard[]                       有序参数列表
      ├─ overrideCameraEffect               相机效果覆盖引用
      ├─ passProfessionMaskFlag             职业筛选标志
      ├─ professionMask                     职业掩码
      └─ playerSideMask                     阵营掩码
```

`GlobalBuffData.useExtraData/extraRuntimeData/source` 在当前原生类型标为 NonSerialized。部分历史正文实际带有这些键，导入时保留并在“其他字段”中显示；新条目不生成它们。

Legacy 符文经原生 `CreateFromLegacy` 转为 `RuneData(key,selector,blackboard)`；现代 selector 的部分筛选值由黑板补入。因此本模块不向 LevelData 条目新增 `selector` 对象。selector 便捷控件必须对应已经核实的黑板键，保存仍写回对应原数组行，不按同名键批量覆盖。

黑板不是参数字典：允许同名键重复，每行的数值与字符串通道分别保留；消费者决定读取哪一个。所有配置数组保留原顺序，资源展示排序不改变正文顺序。

## 3. 本轮全量数据

| 根字段 | 非空正文 | 条目 | 完整配置去重 | 不同标识 |
|---|---:|---:|---:|---:|
| runes | 4,653 | 14,157 | 4,573 | 75 key |
| optionalRunes | 101 | 930 | 475 | 31 key |
| globalBuffs | 2,030 | 2,181 | 525 | 31 prefabKey |

两类符文 key 并集为 76，完整配置合计 5,048 份（两集合没有完全相同的条目）。语料含历史版本，不将 76 或 31 当成当前版本实现总数。黑板分别观察到 520、52、123 个键；以“资源标识＋参数键”管理说明和值域，不跨实现合并同名参数。

49 份正文包含 208 次第二次及以后重复黑板键记录，另有 `env_key ` 尾空格。编辑和导出保留这些数据；搜索使用的归一化文本与保存值分开。

## 4. 左侧编辑模块

保留一个“符文与增益”入口，内部三个同级页签：**关卡符文 · runes**、**可选符文 · optionalRunes**、**全局效果 · globalBuffs**。标题及折叠箭头同框，不使用加粗标题。

### 4.1 集合与条目

- 集合头部展示未提供、null、空集合或条目数；明确的创建、设为 null、移除字段操作。
- runes/globalBuffs 支持列表与块状视图，每项显示原数组序号、资源名或原标识、筛选摘要和参数数。
- optionalRunes 多一层组选择。组内继续复用符文集合控件，支持新增、复制、改名、删除；四种已观察组名只作候选。
- 条目操作：新增、复制、上移、下移、删除。选择条目只切换查看，已有局部草稿保留在自己的目标上。
- 下方编辑框按原生字段顺序排列，提供结构化表单与原始 JSON，字段树定位到同一条目。
- 新增优先复制资源库里明确选中的完整配置；“空白条目”只生成有依据的外层字段，不自动生成所有可能的黑板键。

### 4.2 字段控件

| 字段 | 控件 |
|---|---|
| key / prefabKey | 文本值、资源选择、详情图标；无名称则显示原标识 |
| difficultyMask / professionMask / buildableMask / playerSideMask | 已确认枚举位勾选、原值显示；保留字符串和数值导入形式 |
| passProfessionMaskFlag | 布尔控件；缺失/null 状态仍可辨认 |
| overrideCameraEffect | 字符串编辑和资源候选；语料目前全部 null，不编造推荐 |
| blackboard | 有序行表：key、value、valueStr，支持复制、移动、删除和类型提示 |
| 未知字段 | 原文显示与 JSON 编辑，修改已知字段时原样保留 |

黑板行展开后展示当前实现的参数含义、已确认值域、全部已知值与出处。文字只写事实和来源。有限数值检查与消费者业务范围分开；观察到的最小/最大值仅作样例范围。字符串清空、null 和字段删除是不同操作。已知掩码位切换保留未知位；未识别的枚举字符串先保留原值，不强行转成数值，缺失/null 不因打开控件而自动补默认。

筛选辅助区显示从当前条目解析出的目标条件。角色、敌人、地块及标签候选按对应消费规则提供；敌人筛选使用已证实的关卡内标识时，不替换为图鉴标识。多个条件未全部解析时，只列条件与候选，不显示“最终命中”数量。

### 4.3 引用与组编辑

按规则注册“资源实现＋黑板键＋匹配方式＋目标类型＋消费者依据”。本关可定位目标包括敌人定义、预设、分支和隐藏行动组；外部范围/资源引用单列。全局文本相等只用于调查，不作为自动重命名依据。

原生按 optionalRunes 字典枚举各组，以外部 optionalRuneKeys.Contains(groupKey) 决定是否合入。不是自动启用全部，也不按外部 key 列表的次序重排；外部 key 重复不会使同组重复展开。该默认组展开函数未执行 difficultyMask 检查，编辑器不套用普通关卡符文的难度过滤；字典遍历顺序也不当作跨平台保证。

`optionalRunes` 组名被外部调用方使用时，改名对话框展示该事实。编辑器不能同步修改不在当前文档中的玩法数据；也不将当前选中组标为游戏已启用。

`rune_alias` 等符文间关联保留原字面值；重复 alias 不擅自认定为无效，因为既有预处理可能遍历多个候选。重排保留用户意图，不声称界面顺序就是全部运行阶段的执行顺序。

## 5. 右侧资源库

新增“符文与增益”资源页，内部分“符文”和“全局效果”。右侧只做搜索、预览和选用，字段编辑全部在左侧。搜索复用现有 Angelina 适配路径，不另造搜索算法。

资源详情沿用现有图标及结构：

1. 默认推荐：最多三份完整原版配置，第一项为初始选用项。
2. 全部既有已知配置：块状分页展示完整去重条目，模式掩码、黑板顺序及未知字段差异都保留。
3. 当前配置出处：按关卡分组，关卡下保留模式、版本、LevelData 与原路径。
4. 总出处：该资源所有配置的来源并集，不随当前配置切换缩减。

同一 Legacy 配置可以来自 runes 或 optionalRunes；目录记录原位置和上下文依赖（例如 six_star_rune_alias），左侧选用时明确目标集合/组。跨集合操作复制完整配置，仍展示原用法，不自动改变掩码或补充配套符文；相同条目类型不等于可以脱离原上下文独立生效。配置指纹只覆盖完整条目，不包含其原数组索引和出处。重复正文的镜像来源不抬高推荐频率。推荐按兼容已确认基线优先、独立关卡覆盖数其次、稳定指纹最终排序；无法确认版本兼容的样例仍可查看选用，显示实际来源版本。

现代外部 RuneData 与 Legacy 条目分开，不将模式资源转换为关卡配置并静默导出。全局效果可用实现名或 prefabKey 浏览，头像不是本轮前置条件。

## 6. 数据事务与验收要求

- Core 为三个根字段提供独立不可变命令；optional 组键必须使用 JSON Pointer 转义或结构化地址。
- 黑板编辑、条目移动、组改名、复制选用各为一次撤销事务。
- 重排后迁移草稿地址；删除目标时处理其局部草稿，不将草稿套到后继元素。
- 切换地图时分别保留选择、折叠、滚动、草稿；编辑锁限制数据修改，相机锁不限制表单。
- 全量语料回读验证所有条目，未修改内容保持 JToken 等价；重复键、尾空格、缺失/null、未知字段用专项回归覆盖。
- 结构错误定位到字段；未识别的历史资源值不被自动删除。已确认静态引用可检查，玩法上下文不由本模块补造。
- 本轮是设计与语料核验。后续专用实现通过测试、review 和 Unity 交互验证后再更新“已落地”状态。

## 7. 实施顺序

先完成三个根字段的无损 CRUD 和草稿撤销，再接完整配置目录/出处，随后逐消费者增加黑板与筛选便捷控件，最后接已核实的关联导航。最终属性演算、外部玩法输入编辑和藏品获得流程独立规划。

## 8. 原生消费与编辑预览的分界

```text
LevelData.runes                    optionalRunes + 外部 optionalRuneKeys
       │ 难度有效性检查                      │ 选中组，保持组内条目
       └────────────────┬───────────────────┘
                        ▼
              CreateFromLegacy
              key + 两种 mask + blackboard → RuneData
                        │
                 黑板补充 Selector
                        │
              RuneManager 创建/优先队列
                        │
         符文预处理 → 对象筛选 → 参数/属性消费者
                        │
              后处理、回调及运行期变化

LevelData.globalBuffs
       └─ prefabKey → 原生全局效果加载 → OnInit → 控制器管理
```

图示分开列出两条输入链，不表示它们是一个统一的线性执行序列。完整阶段及外部输入见原生研究。

难度有效性检查为 `(difficultyMask & difficulty) == difficulty`，不是任意交集；difficulty 为 0 时此谓词通过。运行队列还有 priority 和阶段遍历方向，不能将数组显示顺序当成最终叠加顺序。Legacy 转换初始复用黑板引用，编辑器复制配置则创建独立 JSON 副本，避免源目录或别的地图被修改。

原生筛选、属性换算、回调和热更新依赖运行对象。本轮预览展示保存的数据、关联位置和已确认的筛选条件；不生成最终攻击力、最终生命值或“已生效”回执。具体未闭合入口在原生研究中逐项列出。
