## 2. LevelData 的完整相关字段树

```text
LevelData
├─ runes: LegacyInLevelRuneData[]
│  └─ [i]
│     ├─ difficultyMask: Difficulty
│     ├─ key: string                         符文实现注册键
│     ├─ professionMask: ProfessionCategory
│     ├─ buildableMask: BuildableType
│     └─ blackboard: Blackboard              有序 DataPair 列表
│        └─ [j]
│           ├─ key: string
│           ├─ value: float
│           └─ valueStr: string
├─ optionalRunes: Dictionary<string,List<LegacyInLevelRuneData>>
│  └─ 组键 → 与 runes 相同的五字段条目列表
└─ globalBuffs: GlobalBuffData[]
   └─ [i]
      ├─ prefabKey: string
      ├─ blackboard: Blackboard              同上三字段列表
      ├─ overrideCameraEffect: string
      ├─ passProfessionMaskFlag: bool
      ├─ professionMask: ProfessionCategory
      └─ playerSideMask: PlayerSideMask
```

定位：dump 102733–102735、110251–110320、103112–103143；Blackboard.DataPair 在 95283 附近。Legacy 静态 `SIX_STAR_RUNE_NAMES` 不是实例导出字段；RuneData.Selector 不是上述五字段中的一项。

GlobalBuffData 另外有三个 `[NonSerialized]` 字段：`useExtraData:bool`、`extraRuntimeData:ExtraRuntimeData`、`source:IGlobalBuffSource`。ExtraRuntimeData 内为 `sideType`、`extraValidator` 委托、`checkExtraProfession`。这些是运行附加输入，不作为 LevelData 编辑器的新 JSON 字段输出。

## 3. Legacy 与运行 Selector 的转换

```text
LegacyInLevelRuneData
  → RuneData.CreateFromLegacy
    ├─ key
    ├─ selector: Selector
    │  ├─ professionMask / buildableMask     从 legacy 复制
    │  ├─ playerSideMask / sideType
    │  ├─ charIdFilter / charIdExcludeFilter
    │  ├─ enemyIdFilter / enemyIdExcludeFilter
    │  ├─ enemyLevelTypeFilter / enemyActionHiddenGroupFilter
    │  ├─ skillIdFilter / tileKeyFilter / groupTagFilter
    │  ├─ filterTagFilter / filterTagExcludeFilter
    │  ├─ subProfessionExcludeFilter / mapTagFilter
    │  └─ heightTypeMask
    └─ blackboard                           初始共享原黑板引用
  → InitIfNot
    → 从黑板补充 masks 与 filters
  → RuneManager 注册的具体 Rune 类
  → 对应消费阶段 / 目标筛选 / 具体属性或行为修改
```

`CreateFromLegacy` 为 `0x182523040–0x182523100`；InitIfNot 为 `0x1825231F0–0x182523220`。初始化标志先置位，不可假定异常后重试一定重新初始化。

### 默认值及枚举

Legacy 构造 `0x18251D4D0–0x18251D560` 直接写 difficultyMask=1、professionMask=1023、buildableMask=3，并构造 Blackboard；key 为 null。这是类构造默认，不代表每个符文的可运行模板。

- Difficulty：NONE=0、NORMAL=1、FOUR_STAR=2、EASY=4、SIX_STAR=8、ALL=15。
- ProfessionCategory：NONE=0、WARRIOR=1、SNIPER=2、TANK=4、MEDIC=8、SUPPORT=16、CASTER=32、SPECIAL=64、TOKEN=128、TRAP=256、PIONEER=512。
- BuildableType：NONE=0、MELEE=1、RANGED=2、ALL=3。
- PlayerSideMask：ALL=0、SIDE_A=2、SIDE_B=4、NONE=255。此 ALL 是零，不能套普通全位掩码算法。
- SideType：NONE=0、ALLY=1、ENEMY=2、BOTH_ALLY_AND_ENEMY=3、NEUTRAL=4、ALL=7。
- HeightTypeMask：NONE=0、LOWLAND=1、HIGHLAND=2、ALL=3。

Selector 构造默认 profession=1023、buildable=3、sideType=7、height=3、playerSide=0，列表 null。

难度判定已按固定 DLL 字节确认：`(difficultyMask & difficulty) == difficulty`。不是“有任一交集”。difficulty=0 时也返回 true。函数 `0x18251D2F0–0x18251D300`，16 字节范围 SHA256 `6fdf5e8ea0c8a7a22f6e1cb53e03761b39f92d5ee625e0667ec29399c940e236`。

### 有证据的黑板 selector 辅助编辑

| blackboard 字符串键 | 运行目标 | 处理 |
|---|---|---|
| profession | professionMask | 原掩码与解析结果相交 |
| buildable | buildableMask | 原掩码与解析结果相交 |
| player_side | playerSideMask | 替换 |
| side | sideType | 替换 |
| char / char_exclude | charIdFilter / charIdExcludeFilter | 字符串列表 |
| enemy / enemy_exclude | enemyIdFilter / enemyIdExcludeFilter | 字符串列表 |
| action_hidden_group | enemyActionHiddenGroupFilter | 字符串列表 |
| enemy_level_type | enemyLevelTypeFilter | 字符串列表 |
| skill / tile / tag | skillIdFilter / tileKeyFilter / groupTagFilter | 字符串列表 |
| filter_tag / filter_tag_exclude | filterTagFilter / filterTagExcludeFilter | 字符串列表 |
| sub_profession_exclude / filter_map_tag | subProfessionExcludeFilter / mapTagFilter | 字符串列表 |

字符串列表按 `|` 分隔、移除空片段，不 trim、不去重；追加到已有列表，读不到可用字符串时列表设 null。不能把 null、空列表、缺键等同。mask 解析另有内层逗号枚举解析，规则不能与列表拆分混用。对无法解析的原值保持原样，不把 UI 解析失败写成 0。

enemy 筛选比较的是运行 `keyInLevel`，不是敌人数据库图鉴 ID；exclude 优先。action hidden group 精确比较。filterTag 还受具体 Character/Enemy/Trap 类及热更新实现影响。辅助编辑应写回已有黑板条目而不是制造 selector JSON；重复键和 value/valueStr 两通道保持可查看。

## 4. optionalRunes 的选择不是 LevelData 自启动

外部 `SquadHomeStateBeanParam.optionalRuneKeys` 传入 `_GeneOptionalPackedRuneData(List<string>,LevelData)`。PC 默认路径：

1. 输入 key 列表或 optionalRunes 无内容时返回 null。
2. 遍历 optionalRunes 字典条目，以外部 key 列表的 Contains 判断是否选择该组。
3. 命中组内逐项 CreateFromLegacy，加入同一 RuneData 列表。
4. 将该列表装入一个 PackedRuneData，并返回包含该对象的列表；没有展开条目时返回 null。

因此组内顺序保留；外部 key 列表顺序不是执行排序。重复选择同一个 key 不会多次展开；不存在的 key 不匹配任何组。字典迭代顺序不作为跨平台契约。此函数没有调用 Legacy.CheckValidForDifficulty，不能为 optional 组套上普通 level runes 的难度预过滤；后续具体输入接入和热更新仍应按调用上下文确认。

字节定位 `0x18171B010–0x18171B480`，SHA256 `9825def6bbdae4544ac97c92a90082e0f7923a5b0e50c90636595a62946eccb8`；`+0x19F` 读 LevelData+0x50，`0x18171B291` 调 Contains，`0x18171B30C` 调 CreateFromLegacy，`0x18171B3FC` 写 PackedRuneData+0x30。

编辑器负责创建/重命名/编辑组及保留内容。用于演示的“已选择组”是编辑器预览状态，不自动写成新 LevelData 选择字段。组名重命名不能声称同步了私服或玩法外部引用。

## 5. 原生入口、排序与叠加

BattleController `_InitRunes(IRuneDataHolder,IList<LegacyInLevelRuneData>,Difficulty)` 位于 `0x180639280–0x180639660`。运行输入不只有 LevelData；IRuneDataHolder、PackedRuneData 以及玩法模式提供额外输入。PackedRuneData 的 id/points/mutexGroupKey/description/runes 属于另一结构，不应摊平成 Legacy 额外字段。

RuneManager 入口：CreateLegacyRune `0x180CE4330`、CreateRune `0x180CE4510`、IsRuneKeyValid `0x180CE4670`、注册类 `_RegisterRuneClasses 0x180CE6330`。key 对应实现类注册，不是任意描述文本。

RuneTarget 位：LEVEL_OPTIONS=1、CHARACTER=2、ENEMY=4、LEVEL_DATA=8、MAP=16、CARD=32、BATTLE_PLAYER_DATA=64、RUNE_DATA_PRE=128、DECK_DATA=256。只有对应阶段与目标被调用才能产生效果。

既有离线复核确认：priority 比较为 Int32；PriorityQueue.Add 遇 <= 插在当前项前，同优先级逆插入序。RuneData 预处理和完成回调逆遍历，敌人预处理正向遍历；之后还有倍率缓存消费。因此保持输入列表顺序，但 UI 不应将它解释为全链唯一执行顺序。

`ROtherRuneBlackboardAdd` 依赖 rune_alias、目标位128及目标有效性；AddBlackboardStrictly 仅对已有数值行加匹配的第一个数值源，不插入缺键。不能把同 key 符文或黑板条目自动合并。

属性倍率链包含 FP 转换、字段范围 Clamp、反射写回，分组加算再乘算不能压成普通浮点乘法。既有静态绑定已证明 maxHp/atk/def 为 ObscuredInt、magicResistance 为 ObscuredFloat，以及对应 FieldInfo 槽位。正常尾部才清缓存；异常先 Dispose 再传播，可能保留缓存及已写入的部分属性，不提供事务回滚。完整热更新运行效果仍未由这些静态研究签收。

## 6. GlobalBuffData 不是 BuffData

```text
LevelData.globalBuffs[] / RuneLevelExtraOutput.globalBuffs / 外部输入
  → BattleController.CreateAndInitGlobalBuff(data)
    → BattleFactory.CreateGlobalBuff(data.prefabKey)
      → GlobalBuff 或其派生组件
        ├─ prefab _options: TargetOptions
        ├─ prefab _buffs: BuffData[]
        ├─ prefab _deckBuffs: DeckBuff[]
        ├─ prefab _overrideCameraEffect / _sourceType
        └─ OnInit(data) → 运行 blackboard / 筛选 / 相机覆盖 / 来源
          → TryAddBuff(unit) / TryRemoveBuff(unit)
            → BuffData + 单位 Buff 系统
```

固定入口 `CreateAndInitGlobalBuff 0x18061D190–0x18061D340` 范围 SHA256 `378e77e1d7ee43e2dbdb4d72d93d831ea1d509104387a508dfd557d5bf7b2bf5`：`0x18061D243` 读取 data+0x10，`0x18061D24D` 调 BattleFactory.CreateGlobalBuff `0x1808E9340`，虚调用 OnInit 后加入 controller 全局列表。不是直接把 prefabKey 当 BuffData.buffKey。

GlobalBuff dump 239690 起：OnInit `0x18072E3B0–0x18072E8B0`、TryAddBuff `0x18072EC50–0x18072F1D0`、TryRemoveBuff `0x18072F3B0–0x18072F830`；有 GlobalBuffWithInterval、绑定地块等派生实现。OnInit 可见读取 blackboard、overrideCameraEffect、passProfessionMaskFlag/professionMask、playerSideMask 及运行额外数据。绑定单位的完整选择规则还依赖 prefab TargetOptions、派生类以及模式上下文，不能以六字段单独推断全部命中对象。

GlobalBuffData 无自定义赋值构造（`0x18050FCC0–0x18050FCD0`）：引用 null、数值0、bool false。不会默认构造 Blackboard 或自动填入一个可加载 prefabKey。

BuffData（dump 95375）进一步管理：attributes、buffKey、loadFromDB、templateKey、blackboard、overrideKey/overrideType、叠层数量与时间、source 独立性、触发次数/间隔、事件优先级及状态可抵抗性等。overrideType 明确有 DEFAULT/STACK/UNIQUE/EXTEND/EXTEND_TIME；BuffTemplateDBData 包含 templateKey/effectKey/onEventPriority/eventToActions。它们是被 prefab/数据库/行为节点读取的下层定义，不是 globalBuffs[i] 可直接追加的字段。

## 7. 与路线、波次、分支、预设的关系

- LevelData 三个容器没有通用 routeIndex、branch_id 或预设 alias 固定字段。关联通常存在于具体符文黑板和具体消费类内。
- enemy 筛选使用关内敌人键；action_hidden_group 对接出怪动作隐藏组，不能按 enemyDbRefs.id 替换全部字符串。
- RuneLevelExtraOutput 包含 globalBuffs、globalEnvSystemDatas、levelScriptRuneDatas、extraDisableLocations、enabledHiddenGroups、disabledHiddenGroups。符文可以改变地图/脚本/出怪组上下文，不能仅做战斗属性表。
- PreloadRuneKey 中存在 env_system_new、env_gbuff_new、env_level_script_new、env_gbuff_new_with_verify、env_gbuff_add_with_higher_priority、insert_token_card 等。它们提示关联入口，不足以把所有对应黑板格式宣布为统一 schema。
- 预设角色/装置及卡牌是后续消费者对象，是否受某符文影响取决于阶段、mask、filter、派生实现；不自动复制预设全部属性到符文。
- branches/waves 重命名及别名修改只更新已证结构化引用；未知黑板字符串先保留并提示检查，不批量猜测重写。

## 8. 可实施约束与剩余证据

可以直接实施：三个 LevelData 容器独立编辑；Legacy 五字段表单；globalBuff 六字段表单；Blackboard 有序逐行编辑；已证枚举选项；可加载资源和已知样例选择；optional 分组；保序复制/移动/删除；缺失、null、空集合及未知字段无损往返。枚举允许保留历史未知数值，不以当前已知样本封闭全部取值。

已证 selector 黑板键可作为辅助表单，但应显示实际写入键，保留重复行、两通道和原字符串；不能悄悄规范化空白、顺序、大小写、重复或未识别值。数值默认由具体消费代码或具体样例注明；不将 constructor 零值称为每个符文安全有效值。

尚未闭合：所有具体 Rune/Buff 派生类的逐键域和缺省；GlobalBuff prefab资源路径到 AssetBundle 的完整目录及依赖；每个 TargetOptions/派生选择器；外部玩法输入的完整组合顺序；跨来源/热更新分支的排序与实际效果；任意黑板内动态关联的重命名安全性。没有这些证据不阻塞数据编辑器，但阻止宣称完整效果模拟或统一黑板总表。

本轮新增验证为固定 DLL 静态反汇编核对和既有研究交叉阅读；没有新增运行测试或实机验收。
