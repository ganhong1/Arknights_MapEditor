## 已认可的实施范围

首版处理 `LevelData.waves[]`，顺序为 Wave → Fragment → Action。编辑器支持三层浏览、新增、复制、重排和删除，首个结构化动作是 `SPAWN`。它引用本关已定义的敌人和独立路线模块中已应用的主路线。首版显示相对调度时间与阻塞状态，用空白地图和 5-10 验收。

第二阶段接入 `branches` 的 Branch → Phase → Action，复用动作表单，并用 AW-6 核对额外路线。随后补预设别名动作，使用 5-10 的 `faust_ballis` 验证。随机组、模式刷新和精确战斗时序仿真列入后续阶段。各阶段均保留导入正文中的未知动作、字段和原值。

## 首版工作台操作

- 「波次」直接显示 `waves[] → Wave → fragments[] → Fragment → actions[] → Action`。父级字段穿插在树中，保留声明顺序。展开后可新增、复制、上移、下移、删除或定位中央字段树。搜索复用资源库的 Fuse 工具。
- 「新增出怪」先生成局部草稿。选好本关敌人及主路线后可创建。动作的常用字段与全部字段沿原始声明排序，全部字段同时显示导入扩展键。其他动作可查看字段并通过原始动作 JSON 进行编辑。旧版分支动作入口位于「分支」。
- 已应用的片段提供相对时间轨，展开的动作同时显示自己的时间区间和阻塞状态。路线定位和演示复用场景中的 PRTS 路线系统。5-10 首片段的 `DISPLAY_ENEMY_INFO` 保留原始路线值，`SPAWN` 显示并可演示 `routes[1]`。
- 复制、移动及删除为独立文档操作，支持撤销。波次内重排同步更新局部草稿路径，删除节点后保留其未应用草稿供复制或清理。无法安全重绑定的旧版草稿显示在「待处理波次草稿」。
- 2026-11-14 用 Unity 2021.3.39f1 验证空白图、5-10 与原版空波次关卡 `act1arkhub_01`。波次相关 5 项通过，全量 EditMode 415 项通过、8 项跳过。当前工作台打开独立「5-10 波次演示」标签，已核对 `routes[1]` 的场景预览。原有六个标签的正文及草稿哈希、206 个既有恢复文件哈希一致。

## 完整配置树

Wave 管一波何时开始、如何清场和何时推进。Fragment 是一段共用时间起点的动作队列。Action 记录具体操作及目标。一波可以包含多次出怪和展示事件。出怪动作以 `key` 选本关敌人，以 `routeIndex` 选路线，敌人定义和路线几何由各自字段持有。

```text
LevelData
├─ waves: WaveData[]
│  └─ WaveData
│     ├─ preDelay: float
│     ├─ postDelay: float
│     ├─ maxTimeWaitingForNextWave: float
│     ├─ fragments: FragmentData[]
│     │  └─ FragmentData
│     │     ├─ preDelay: float
│     │     └─ actions: ActionData[] → 下方共用结构
│     └─ advancedWaveTag: string
├─ branches: ListDict<string, BranchData>
│  └─ 分支key → BranchData
│     └─ phases: PhaseData[]
│        └─ PhaseData
│           ├─ preDelay: float
│           └─ actions: ActionData[] → 同一个ActionData类型
├─ enemyDbRefs[] → 出怪动作key关联的敌人定义引用
├─ enemies[] → 内嵌敌人定义，不能用只检查enemyDbRefs替代完整解析
├─ routes[] → 主路线库
├─ extraRoutes[] → 额外路线库
├─ predefines → 基础预设
│  ├─ characterInsts[] / tokenInsts[] → 场上记录，含 alias
│  └─ characterCards[] / tokenCards[] → 卡牌记录
├─ hardPredefines → 困难预设，结构同 predefines
├─ bgmEvent → 关卡背景音乐入口
└─ operaConfig → PLAY_OPERA 使用的演出资源键

ActionData
├─ JSON 字段（按声明顺序）
│  ├─ actionType                        : ActionType
│  ├─ managedByScheduler               : bool
│  ├─ key                              : string
│  ├─ count                            : int
│  ├─ preDelay                         : float
│  ├─ interval                         : float
│  ├─ routeIndex                       : int
│  ├─ blockFragment                    : bool
│  ├─ autoPreviewRoute                 : bool
│  ├─ autoDisplayEnemyInfo             : bool
│  ├─ isUnharmfulAndAlwaysCountAsKilled : bool
│  ├─ hiddenGroup                      : string
│  ├─ randomSpawnGroupKey              : string
│  ├─ randomSpawnGroupPackKey          : string
│  ├─ randomType                       : RandomType
│  ├─ refreshType                      : RefreshType
│  ├─ weight                           : int
│  ├─ dontBlockWave                    : bool
│  └─ forceBlockWaveInBranch           : bool
├─ [NonSerialized] 运行时字段
│  ├─ useExtraRoute                    : bool
│  ├─ isValid                          : bool
│  ├─ notCountInTotal                   : bool
│  ├─ extraMeta                        : object
│  └─ actionId                         : LevelData.ActionID
│     ├─ subSchedulerI                 : int
│     ├─ waveI                         : int
│     ├─ fragI                         : int
│     └─ actionI                       : int
└─ [JsonIgnore] weightValue             : float，只读，取 (float)weight
```

新建动作按原生 JSON 字段写入。导入时保留历史正文中的运行字段同名键及扩展字段。PhaseData 的随机候选与命中结果缓存属于运行态。

## 首版数据架构

| 层 | 数据职责 | 编辑器处理 |
| --- | --- | --- |
| Wave | 有序片段、波次前后延时、清场等待上限、`advancedWaveTag` | 编辑波次字段。`advancedWaveTag` 保留原值及缺失状态，按字符串编辑，具体模式含义以各自的消费证据为准。 |
| Fragment | 片段前延时及其动作序列 | 管理所属 `actions[]`。时间视图以片段为局部时间基准。 |
| Action | 动作类型、目标、数量、时间、阻塞及其他原生参数 | `actionType` 决定显示哪些字段、如何解析 `key`，以及是否读取 `routeIndex`。首版给 `SPAWN` 专用表单。 |
| 引用目标 | `enemyDbRefs[]`／`enemies[]` 定义敌人，`routes[]`／`extraRoutes[]` 定义路线，预设层定义场上或卡牌输入 | 编辑动作时只选用目标。敌人定义、路线几何和预设配置仍在各自模块修改。 |

原生保存路径是 `waves[wi].fragments[fi].actions[ai]`。Wave、Fragment 和 Action 按数组位置定位。前端选中、展开和滚动归当前地图的编辑会话。运行时 `actionId` 由游戏持有，编辑器的节点选中状态也留在 LevelData 之外。

读取旧正文时，编辑视图从原 JSON 投影字段。应用时以文档事务修改目标字段和数组，保留缺失、null、空数组、未知字段以及动作枚举的原有表示。切换动作类型时保留已有字段，适用性由当前类型决定。动作键缺失或引用越界时显示实际路径，用户显式选择有效目标。后续分支阶段复用动作表单及校验，按分支键和 Phase 索引寻址。

## 动作枚举与引用

PC 2.7.81 默认原生路径声明 15 个枚举值，注册 13 个执行器。以下按动作专用读取列出；共同的调度参数见表后。

| 值 | actionType | 该类型实际读取 | 引用来源 |
| ---: | --- | --- | --- |
| 0 | SPAWN | `key` 查敌人，`routeIndex` 选路线，`count`、`interval` 展开出怪；`autoPreviewRoute`、`autoDisplayEnemyInfo` 派生动作。执行器还读 `managedByScheduler`、`isUnharmfulAndAlwaysCountAsKilled`、`dontBlockWave`、`forceBlockWaveInBranch`、`hiddenGroup`、`useExtraRoute`、`extraMeta` 和动作级 `notCountInTotal`。 | 敌人表由 `enemyDbRefs[]`、`enemies[]` 与可用的运行时补充定义建立。路线来自主波次 `routes[]` 或分支 `extraRoutes[]`。 |
| 1 | PREVIEW_CURSOR | 只以 `routeIndex` 和运行时 `useExtraRoute` 定位预览。入队将 `count`、`interval` 写成 2 次、0.3 秒。 | 主波次 `routes[]`、分支 `extraRoutes[]`。 |
| 2 | STORY | `key` 交给 StoryDB 检查并由 AVG 播放。 | 外部剧情资源。 |
| 3 | TUTORIAL | `key` 走同一 StoryDB、AVG 入口，使用独立执行器与完成回调。 | 外部教学剧情资源。 |
| 4 | PLAY_BGM | `key` 作为 `ON_CUSTOM_TRIGGER` 子信号交给 BattleBGMManager。 | 音频事件。顶层 `bgmEvent` 是独立输入。 |
| 5 | DISPLAY_ENEMY_INFO | `key` 查敌人表的图鉴条目并发出展示事件。 | 与 SPAWN 共用本关敌人表，可在出怪前执行。 |
| 6 | ACTIVATE_PREDEFINED | `key` 为一个预设别名。尝试解除同别名卡牌的 `deck_default_hidden`，也尝试生成同别名场上预设。 | 当前生效的 `predefines`。原生 FOUR_STAR 的困难训练路径按第三项复核选择预设数组。场上查 `characterInsts[]`、`tokenInsts[]`，卡牌查活动牌组。 |
| 7 | PLAY_OPERA | `key` 匹配 `OperaCommand.key`，同时传整条 ActionData。部分节点读取 `routeIndex` 与 `useExtraRoute`，见第五项复核。 | `LevelData.operaConfig` 选演出资源，动作 `key` 选其中的命令，具体节点可依赖路线或场景。 |
| 8 | TRIGGER_PREDEFINED | `key` 接收别名与能力名。竖线分隔候选，随机选一个。省略能力名时用 `DefaultTrigger`。 | 已在场的别名实例及其挂载能力。 |
| 9 | BATTLE_EVENTS | 把整条 ActionData 和回调交给当前玩法。默认玩法仅完成回调。保全派驻读取 `key` 处理抽牌或重抽，生息演算读取 `WaitBase` 等待基地落位。 | 玩法或场景组件的事件。主线 15-17 的 `battle_event_prts_error` 由关卡环境监听器按 `actionType` 和 `key` 匹配。 |
| 10 | WITHDRAW_PREDEFINED | `key` 为单个预设别名，查找并撤回场上实例。 | 生效预设的 `characterInsts[]`、`tokenInsts[]`。 |
| 11 | DIALOG | `key` 交给战斗对话控制器，等待对话结束。自动代理分支跳过启动对话。 | 外部战斗对话资源。 |
| 12 | SHOW_ALL_HIDDEN_CARDS | 无专用动作字段。遍历活动牌组，对卡牌尝试解除 `deck_default_hidden`。 | 活动牌组中的卡牌，包括已装入牌组的关卡预设卡牌。 |
| 13 | EMPTY | 无执行器。主随机预处理使用组键、包键、权重和空 `key` 表示不生成的候选。 | 当前片段的随机候选。分支也能按组收录动作，现有分支抽取方法未见同样的空键剔除，避免把 EMPTY 直接当成可执行分支动作。 |
| 14 | E_NUM | 枚举末尾标记，无执行器。 | 无。 |

- 入队读取 `actionType`、`preDelay`，叠加片段或阶段前延时。`blockFragment` 参与主波次的完成回调计数。分支执行器接收空回调，阶段推进另有控制条件。除 SPAWN 和 PREVIEW_CURSOR 外，有执行器的动作每条入队一次。
- 主片段用 `hiddenGroup` 对照启用集合。字段为 null 时通过默认检查，非 null 时查集合。主波次分派前发送 `ON_BEFORE_LEVEL_ACTION_EXECUTE`，随后检查 `isValid`。关卡监听器可以先于执行器读取动作。
- `RandomType`、`RefreshType` 各自声明 `ALWAYS=0`、`PER_DAY=1`、`NEVER=2`、`PER_SETTLE_DAY=3`、`PER_SEASON=4`。已核对的主波次随机、分支抽取和外部结果预处理入口未直接读取这两个字段。
- 动作表单按类型选择目标。SPAWN 和 DISPLAY_ENEMY_INFO 选本关敌人，PREVIEW_CURSOR 只选路线，三种单预设动作分别按激活、触发、撤回的要求过滤别名候选。PLAY_OPERA 和 BATTLE_EVENTS 的扩展字段只有在对应消费者明确时进入专用表单。

## 关联与时序

1. waves 与 branches 为并列字段。主波次用 fragments，分支用 phases。共享动作表单，不共享父级序列假设。
2. Scheduler.TryMoveNextBranch(branchId,isLoop)、TryPickRandomBranch、TryPickRandomBranchNotRepeat 表明分支可顺序、循环或随机调度。ActionType中没有一个通用“执行分支”枚举。不能从branches存在推导其自动运行，也不能自动追加虚构动作。
3. 出怪 `key` 与预设 `alias` 属于不同命名空间。路线用数组索引，编辑器可用内部稳定标识处理移动，导出仍写原始索引。调度器先登记成功解析的 `enemyDbRefs[]`，再补同键尚未占用的 `enemies[]`。主波次预加载与模式查询有独立读取规则，见 [敌人专项复核](敌人资源库数据设计.md#内联敌人的读取入口同键优先级与版本沿革)。
4. `_DealAction` 给 `SPAWN` 和 `PREVIEW_CURSOR` 设置 `useExtraRoute = fromBranch`。主波次查 `routes[]`，分支查 `extraRoutes[]`。路线编辑已统一预览、校验和重排的解析，历史字段仍保留在原 JSON。动作表单沿用同一规则。
5. 5-10的faust_ballis有7个Phase，共10次ACTIVATE_PREDEFINED，key依次关联trap_007_ballis#1至#10。场上记录hidden=true，inst.characterKey均为trap_007_ballis。alias定位具体记录，类型ID不能替代alias。浮士德技能的调用链见第二项复核。
6. preDelay、postDelay、interval是相对调度参数，blockFragment、dontBlockWave及分支阻塞参与推进条件。不能仅将所有延时相加画成确定的全局时间。阻塞与超时方法体已补核，见下方2026-11-12深化结论。
7. 当前预设删除保护是粗粒度的：存在预设动作就阻止删除。后续应按已解析目标区分实际引用、疑似引用和外部运行引用，不将这项能力写成已完成精确别名分析。

## 前端方案

保留左侧“波次”和“分支”两个按钮。主页面保持字段树/JSON，SceneView继续地图展示，不新开强制浮动窗口。

波次模块从上到下：可搜索波次树 → 所选节点字段表单 → 当前动作表格 → 关联详情。左抽屉窄时上下排布，宽时允许树与属性并排；共用现有拖拽分隔线。

树使用 Wave → Fragment → Action 三层，独立保留展开、选中和滚动位置。选择父节点就编辑其原生字段，不额外引入保存到LevelData的“配置组”。动作行显示类型、目标、数量、延时、间隔、路线、阻塞摘要；支持列表/块状切换。

Wave表单按声明顺序显示5字段；Fragment显示preDelay与actions；Action提供常用表单与全部字段两种视图，全部字段按原声明顺序。切换类型保留未适用字段原值，不静默清空。关键目标显示中文名与实际key/alias，信息按钮复用已有图标。

`SPAWN` 表单分别选择本关已定义的敌人和已保存的路线，写入动作的 `key` 与 `routeIndex`。主波次提供 `routes[]`，分支提供 `extraRoutes[]`。路线选择器显示库名、索引、起终点与移动方式，点击可在 SceneView 定位并复用 PRTSMap 路线演示。路线先在 [场景路线编辑](Unity编辑器总体设计.md#场景路线编辑设计) 中独立绘制，敌人定义由原模块维护。

预设动作目标列表显示基础/困难层、干员/装置、名称、alias、坐标或卡牌身份。按动作类型限定已核实的适用记录；不能确认的key保留文本输入并显示待解析，不自动绑定第一条同名记录。跳转关卡预设后保留动作草稿和返回位置。

分支模块使用 key → Phase → Action；Phase/Action复用控件，父级不显示Wave的postDelay等不存在字段。显示“被谁引用”和已知外部触发线索，不能因文档内没有引用就自动删除分支。

## 深化结论与前端修订（2026-11-12）

本节记录固定 DLL 的默认原生路径。敌人定义见 [敌人资源库设计](敌人资源库数据设计.md)，当前开发顺序见 [实施计划](PlanDocumentsForImplementation/UnityEditor/Unity编辑器主实施计划.md)。

### 阻塞、超时与时序

- 波次顺序：前延时 → 依次处理Fragment → 清场等待 → 后延时。最大等待从Fragment全部完成后的清场阶段起算，不解除Fragment内部等待。
- 仅存在下一波且MathUtil.GE(wait,0)成立时启用限时；最后一波不采用此超时。GE(float)含约1e-5容差，不能概括为任意负值都无限等待。典型-1走无限等待。
- 固定步等待至少一次；0不等于同调用内立即结束。帧数为max(1,RoundToEven(time/deltaPlayTime))，中点取偶数，方法体与汇编均已核对。
- 清场检查基于当前波管理敌人列表，并允许GameMode覆盖，不等于全场所有敌人必须消失。
- Fragment先执行完整动作队列，再等待blockCounter归零。SPAWN在生成/失败后回调，不等待敌人死亡。blockFragment因此应叫“等待动作完成”，不能显示为“等待击杀”。
- Branch Phase没有同样的Fragment计数等待；可受外部actionBlockTimer及blockGameKey影响。
- 出怪有效不阻波：dontBlockWave || (fromBranch && !forceBlockWaveInBranch)。显式dontBlockWave优先；managedByScheduler等运行条件另影响是否登记管理列表。
- 动作队列按offset排序；SPAWN offset=max(0,fragment.preDelay+action.preDelay-delayToBorn)+i*interval。其他普通动作是片段/阶段延时加动作延时。显示调度时刻与出生时刻应分开。

例如：片段前延时 2 秒，出怪动作前延时 1 秒，数量 3、间隔 0.5 秒，配置上的相对出怪时点为 3.0、3.5、4.0 秒。原生入队另考虑出生补偿与固定步；正文顺序描述动作下标，同刻原生执行顺序由队列排序决定。

### 路线

`_DealAction` 对 `SPAWN` 和 `PREVIEW_CURSOR` 强制 `useExtraRoute = fromBranch`。主波次选 `routes[]`，分支选 `extraRoutes[]`。动作界面显示解析后的库名，历史字段在原始 JSON 中可查看。

PREVIEW_CURSOR执行前固定count=2、interval=0.3。autoPreviewRoute会派生预览动作，首次出怪调整时间前3秒；不把派生动作写回数组。其他有执行器的动作每条只排一次。

### 随机组与权重

- DefaultSchedulerPreprocessor默认空操作，不能认为所有关卡都执行主随机预处理。
- RandomGroup预处理只纳入SPAWN/ACTIVATE_PREDEFINED/EMPTY的非空组键，作用域为Wave+Fragment+groupKey。每组选一个；删去其余，并按被删项packKey连带删除该Fragment包项。空key可表示“不生成”候选。
- Branch Phase按当前Phase的groupKey选取，中选packKey正向启用同包动作；refreshResult=false复用缓存。这与主波次删除传播不同。
- DataDriven路径读取外部有效动作与剩余数量，不由本地重新随机替代。
- Branch RandomUtil按权重总和取随机数，依序比较并减权重，兜底末项；空列表null。主路径走IBattleRandom接口，不把它等同同一个随机数实现。
- 这些入口未直接读取 randomType 或 refreshType，日期与季节刷新仍需追到玩法或外部输入的实际消费者。编辑器保留原枚举和数值，不显示为局内刷新秒数，不强制归一化权重为百分比。

### TRIGGER_PREDEFINED

key语法：alias[:abilityName]|alias[:abilityName]…；先随机选一个候选，再解析alias和能力名。省略能力名用DefaultTrigger。先找已在场Character，再找附加能力并触发；不会创建预设，也不是对每个候选依次触发。配置卡牌但尚未部署不能视为已有目标。

前端提供候选行：目标alias选择器＋能力名；允许回看原字符串。能力候选来自实际附加能力证据，不从技能显示名猜测。缺目标/能力提前列诊断；原生错误分支并非均立即终止。

### 前端最终调整

1. 保留Wave/Fragment/Action与Branch/Phase/Action两种父树，共用字段组件，不混同推进规则。
2. 超时标为“片段完成后的清场等待上限”；末波显示该值不参与此结束判定。
3. 将“等待动作完成”和“生成敌人是否阻波”分开，旁边展示由flags计算的有效结果。
4. 随机设置保留group/pack/weight原字段，显示作用域及当前解析路径；外部输入未取得时不显示伪造概率或确定结果。
5. 路线库自动由动作所在主/分支上下文确定；预览派生行为只读展示。
6. 敌人目标从当前地图已加载定义选择；目标缺失提供定位定义/外部上下文，不自动从资源库补入。
7. 当前阶段讨论数据架构，结构化波次表单列在实施计划中。
