## 匹配规则与歧义

PC 2.7.81 原生非热更路径中，`GetEnemyIconId` 使用 `String.Format("{0}", enemyId)`，不剥离后缀、不改大小写。`LoadEnemyIcon` 直接将输入 ID 传入自动图集加载方法。该方法在图集或键缺失时返回 `null`。不得用去掉 `_2`、`_3` 等字符串猜测代替资源映射。

五个基线 prefabKey 候选：

| 数据库 ID | 显式模型键及已有头像 |
|---|---|
| enemy_2001_duckmi_2 | enemy_2001_duckmi |
| enemy_2002_bearmi_2 | enemy_2002_bearmi |
| enemy_2034_sythef_2 | enemy_2034_sythef |
| enemy_2085_skzjxd_2 | enemy_2085_skzjxd |
| enemy_8019_pollut_3 | enemy_8019_pollut_2 |

这些是编辑器可采用的共用头像候选，不是 LoadEnemyIcon 的自动回退行为。

历史样例从完整配置的 `overwrittenData.prefabKey` 或内嵌 `enemies[].key` 取明确关联；其中 18 个 ID 在不同配置中出现多个模型键。资源卡片可显示代表图，选用配置后左侧及配置详情必须跟随该配置切换，不将多个模型静默归为唯一图片。剩余20个历史 ID 的目标集中在 `enemy_10041_cnvfire`、`enemy_2095_skzamf`、`enemy_2096_skzamj`。

## 接入建议

1. 装置复用现有图集和 TryGetIcon，无需重建一套图片。
2. 敌人新增固定版本的头像映射与图集，保存 sourceVersion、iconId、UV、资源哈希，界面复用干员卡片布局和虚拟列表。
3. 模板详情中的头像依据所选配置解析；精确 ID 优先，显式 prefabKey 候选另有来源标识，未覆盖项使用区分机制的标记。
4. 图像保持原比例，装置模型缩略图使用等比留边，避免按干员头像裁剪方式切掉关键部件。
5. 当前不因名字相同或图片相同合并资源条目，不将图片键写入 LevelData 原生定义。

## Unity 资源库接入（2026-11-13）

装置列表与详情直接使用 `PrtsObjectView.TryGetIcon`，沿用骨架层的原图集和补充图集。详情显示对应的图源类别，以及索引中已有的资源路径、URL 或机制名称。

敌人资源按固定 2.7.81 快照生成。 `tools/build_enemy_portraits.py` 读取已核验的本地证据、逐图校验 SHA-256，再按图像哈希共享图集位置。 `enemy-portraits.json` 记录图源、资源路径、资源包、图片哈希和 UV 位置。4 张图集提供 2,070 张不同图片，Unity 在列表绑定时按需载入页。原版头像与模型缩略图等比留边，特效以可见范围加留边后等比缩放。

2,445 个敌人条目包括 2,192 个基线 ID 和 253 个历史 ID。基线以精确原版头像优先。18 个有多个已核验预制体的历史 ID，列表使用按预制体键稳定排序的首个图源，详情按所选场景配置匹配。模型、特效、预制体关联、召唤者关联和装置特效各自显示图源标签。图源索引独立于 LevelData。

Unity 2021.3.39f1 EditMode 测试通过 380 项，跳过 8 项。资源库测试逐条绑定 847 项装置和 2,445 项敌人的列表头像，核对图集和 UV，并验证详情图源与历史预制体切换。最终图集的 2,070 个图块均通过透明通道和边界核对，导入后在实际工作台检查了装置、敌人和详情显示。冷启动恢复了五个地图标签，正文、草稿、原文件和美术配置均与恢复副本相符，两份未应用的局部编辑继续保留。
