# 2.7.81 敌人数据与 PRTS 筛选交叉核验

本次核验覆盖 Unity 敌人目录的固定数据库、原版图鉴，以及 PRTS「敌人一览」按皮肤提供的两套筛选。用户截图所示旧版为四组基础筛选和六组评级，新版为五组基础筛选和八组评级。两套使用同一数据页。两版交叉验证都定位到同一处移速评级差异。

Wiki JSON 没有内部 enemyId。对齐修订使用 `(sortId, enemyIndex)` 配对，再用去掉首尾空白的名称核验，然后由本地图鉴取得 ID。原文名称 1,726 条相同，另外 11 条仅尾随空白不同。公开图鉴和 Wiki 对齐快照的覆盖量为固定数据库的 79.24%，占整个资源库的 71.04%。其余是 57 条隐藏图鉴、398 条未入图鉴的数据库敌人和 253 条历史关卡专有 ID。

现行修订的编号与名称按多重集合计数仍覆盖全部 1,737 条，并多出 37 条。编号会重复，对齐修订有 20 条重复编号余量。坎诺特同时重复编号、名称和 Wiki 链接，两个游戏 ID 分别为 `enemy_2036_syshop` 和 `enemy_2153_shcan`。因此内部 ID 来自本地图鉴，同期排序字段用于离线核验，Wiki 链接作为详情资料。 [Wiki 对齐修订](https://m.prts.wiki/index.php?oldid=443233) · [Wiki 现行数据页](https://prts.wiki/w/敌人一览/数据)

## 字段交叉验证

| 标签或资料 | 本地来源与换算 | 对齐结果 |
|---|---|---:|
| 地位 | 图鉴 `enemyLevel` | 1,737 / 1,737 |
| 行动方式 | 数据库 Lv.0 `motion` 的 WALK、FLY，未定义显示未知 | 1,615 条已知全部一致，122 条未知全部对上 |
| 种类 | 数据库 `enemyTags` 通过图鉴 `raceData` 转名。公开图鉴中无种类映射的 1,081 条归其他 | 1,737 / 1,737 |
| 攻击方式 | 数据库 Lv.0 `applyWay`。ALL 同时含近战、远程，NONE 表示不攻击，未定义显示未知 | 1,731 条已知全部一致，6 条未知全部对上 |
| 伤害类型 | 图鉴 `damageType[]`，按集合比较 | 1,737 / 1,737 |
| 生命、攻击、防御、法抗、攻击间隔、元素抗性、损伤抵抗评级 | 数据库 Lv.0 数值与图鉴 `levelInfoList` | 各 1,729 / 1,729 |
| 移速评级 | 同一套评级规则 | 1,728 / 1,729 |
| 能力检索正文 | 图鉴 `abilityList[].text`，归一化 Wiki 展示标记、换行、提示框后比较 | 1,597 / 1,597 条非空一致，140 条均为空 |

图鉴的 `enemyTags` 和 `attackType` 字段在该快照全为 null。读取它们会丢失种类和攻击方式。数据库的 `levelType` 与图鉴地位有 29 处差异，战斗定义的名称有 15 处差异，例如数据库名「持盾刀兵」对应图鉴名「机动盾兵」。目录用图鉴名称和地位，保留数据库名作为检索别名，战斗定义仍保留原始字段。

攻击方式有 85 条是近战兼远程，伤害类型有 41 条是混合类型。未定义的行动、攻击方式保留缺失标记，避免合成默认 WALK、MELEE 进入图鉴筛选。8 条图鉴设 `invisibleDetail`，与 Wiki 八项均显示 `?` 的条目相同。

评级按图鉴阈值的半开区间 `min ≤ x < max`，`max = -1` 表示无上限。攻速评级用 `baseAttackTime`，单位为秒。元素抗性对应 `epDamageResistance`，损伤抵抗对应 `epResistance`。唯一差异 `enemy_2056_smedzi`（无垠回荡克雷松）的 `moveSpeed` 序列化为 `m_defined=false,m_value=0.0`，按当前定义合成器的构造默认值为 1.0，对应 A。Wiki 一览评级为 E，词条与哨兵关卡页列出 0.0。建议保留 Wiki 评级的来源标签或在原版图鉴评级中明确登记这条例外。当前数据未验证该字段在客户端图鉴展示路径上为何取 0.0。 [无垠回荡克雷松](https://prts.wiki/w/无垠回荡克雷松) · [ISW-DF 哨兵](https://prts.wiki/w/ISW-DF_哨兵)

关卡数值另做定向对照。固定 5-10 的六个 `enemyDbRefs` 都引用 Lv.0，无关卡敌人定义覆盖。对照 Wiki 敌方情报，六条的 66 个数值字段一致。该关的突袭加成另有 `FOUR_STAR` 符文，评级对照不将它们应用到资源库基础条目。 [5-10 敌方情报](https://prts.wiki/w/Main_05-10)

## 迁移方案

1. 以截图的四组基础标签和六组评级作为工作台默认布局，每行提供全选与清除。行动方式、元素抗性和损伤抵抗已有本地映射，可放进更多筛选。复用预设干员的 UI Toolkit 面板样式及资源库现有来源、有原版配置筛选。
2. 搜索沿用项目算法，索引名称、内部 ID、图鉴编号、描述、能力正文和同版术语解释。将独立描述和编号列为编辑器新增检索字段。能力正文和提示解释都可从本地生成纯文本，不依赖 Wiki 的 HTML。
3. 同组多选取并集，组间取交集，空组放行。逐组全选显式勾选全部可见值，清除撤销这一行的约束。提供「表格／头像」切换，搜索和筛选状态共享。两视图共享当前排序属于可采用的工作台改进，旧版表格和头像各自的排序行为已记录。等级排序应按档位顺序并明确隐藏值位置。
4. 公开图鉴提供与 Wiki 同口径的视图。全部资源视图保留隐藏、未入图鉴和历史条目。图鉴外条目仅展示能从明确的数据库等级或当前所选历史配置取得的标签，伤害类型缺失时保留未知。历史 ID 有多份配置时使用同一份配置判断全部条件，避免把两份配置各自的字段拼成一个命中。
5. 图鉴评级标明 Lv.0。用户切换详情等级或关卡样例时，另用合成定义展示所选等级或覆盖后的数值。关卡模式及运行 Buff 的计算属于关卡实际效果。

新版对照使用上游固定提交的 `toEnemy` 和 `matchFilter` 直接执行 104 个单项及 4 组组合条件。105 组结果集完全相同，3 组只受克雷松移速评级影响。交互逻辑可在 C# 重用，代码仓库为 MIT。站内页面与数据按站方各自声明处理，插件的数据以固定游戏资源为主。 [新版筛选源码](https://github.com/MooncellWiki/prts-widgets/blob/3151f847b113525166c13189f81a67ae2899c1a3/src/widgets/EnemiesListV2/filter.ts) · [MIT 许可](https://github.com/MooncellWiki/prts-widgets/blob/3151f847b113525166c13189f81a67ae2899c1a3/LICENSE) · [Wiki 筛选说明](https://prts.wiki/w/模板:敌人一览补充说明)

## Unity 实现

- 资源库「敌人」的搜索框右侧可展开「标签筛选」。基础筛选、六维筛选和更多筛选通过点击标签选中或取消，面板顶部可清除全部标签。搜索和筛选覆盖全目录，另有「仅显示有原版配置」。
- 列表显示头像、名称、编号和详情按钮，头像网格按宽度换列。两种视图共享关键词、筛选和页码，每页可选 50、100、200 或 500 条。默认按图鉴顺序，搜索时按匹配度。
- 详情集中显示地位、种类、攻击方式、伤害类型、行动方式、六维评级、元素抗性、损伤抵抗、描述和能力。历史条目优先展示本次筛选命中的配置标签。
- 随包索引 `enemy-filters.json` 由 `tools/build_enemy_filters.py` 从固定 2.7.81 敌人数据库、敌人图鉴和术语词典生成。按同一个历史定义匹配组合筛选。检索复用项目的 Fuse.js 与 Bitap，覆盖内部 ID、图鉴编号、名称、描述、能力和术语解释。
- 无垠回荡克雷松的图鉴移速显示采用本地字段存储的 0.0，显示 E。战斗定义保留 `m_defined=false` 及原数据。生成索引对 1,737 个公开图鉴条目的 13 个筛选字段逐项比较，共 22,581 项一致。
