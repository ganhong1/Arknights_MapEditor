# 装置资源库接入与当前工作台验收

日期为 2026-11-06，宿主为 Unity 2021.3.39f1 的既有 WorkbenchDemoProject。此次只修改地图编辑器及离线生成工具，不连接游戏或实验服，不改 APW 原库。

## 已交付界面

右侧资源抽屉中的第二项由「物件」更名为「装置」。目录展示 847 个 ID，其中 403 项有原版预设配置。搜索沿用既有 Fuse.js／Bitap 实现，支持中文名、ID、拼音和首字母；还可筛选仅显示有原版配置的装置。名称去除首尾空白，没有名称则展示 ID。

点击装置行或信息图标打开详情。同一装置分别展示「场上预设」和「卡牌配置」，没有样例的形式显示空态。每种形式独立提供最多三项默认推荐、全部既有配置、当前配置出处和总出处。

全部既有配置以比较投影归组，采用分页块状浏览并支持搜索。每组可切换全部完整原始记录，完整显示 position、direction、hidden、alias、inst、技能与天赋覆盖等字段。当前配置出处跟随所选完整记录，总出处覆盖当前形式的全部配置。出处支持列表／块状显示、搜索与点击预览，预览给出原始配置及正文数组位置。

切换推荐不会重建详情整体，原始 JSON 使用固定高度滚动区域，已展开的当前出处、总出处和全部配置区域保持展开。两种形式的页面保留各自控件状态。没有添加资源库内的跨模块关联检查，没有自动导入分支、波次或改变模式。

## 选用与草稿

「使用这套配置」将完整原始记录载入当前地图的装置编辑草稿，切到「装置」编辑项，并把目标设为 predefines 下对应数组末尾。位置、隐藏标记、别名及未知字段保持原值，用户可在编辑项中修改。

只有明确点击「插入预设」才写入地图。已有未应用草稿沿用原有确认流程，取消后保留原内容与目标。装置目标的层、形式和数组索引在 GUI 刷新及域重载后保留。

交互回归发现并修复了一处实际问题：最初选用动作只更新了草稿存储，编辑框仍显示 `{}`，立即插入会写入空记录。当前改为先构造并校验完整替换草稿，再统一提交存储、显示和目标。新增测试核验立即插入的导出 JSON 与所选原始记录一致，避免仅测刷新后显示而遗漏该路径。

## 数据发布与容量

- 来源为 [装置配置普查](DEVICE_PRESET_AUDIT_20261106.md) 的固定证据，游戏数据提交为 `bb8f9ac8db143a661577ed6ef5184d3c6e93d1d0`。
- 轻量目录 `Editor/Catalog/device-index.json` 为 345,258 字节。
- `Editor/Catalog/DeviceSamples` 共 403 份 JSON，合计 8,274,000 字节，最大单文件 207,325 字节。
- 详细配置按装置读取并最多缓存四个装置，不在打开工作台时解析约 33 MB 的完整研究 JSON。
- 包内数据保留 2,552 组配置、14,003 份完整原始记录和 20,694 条逐位置出处。独立打包回读核验全部原始数据和来源一致。
- 历史三项旧定义与非 trap_ 记录保留，缺原版样例的项不生成虚构默认。

生成器为 [build_device_library.py](../../tools/build_device_library.py)，拼音补充为 [enrich_device_search.cjs](../../tools/enrich_device_search.cjs)。输入、输出和 Toolbox 路径均通过参数传入，运行包没有本机路径依赖。
